## 来源怎样填

每个条目至少一条来源。每条来源写种类、出处、摘录，需要时再写它支持哪几处（`supports`）。种类有五种：

- **文档原文**：出处填材料文件的路径，摘录填文件里支持这个条目的那句原话，逐字照抄，不要改写。摘录必须逐字抄自材料里连续的一段：不要把不相邻的几句接在一起，也不要改字、漏字。工具会拿摘录到出处所指的文件里逐字查找，找不到就整次拒绝。一条来源只抄材料里连续的一段；条目用到材料里不相邻的几处，引了几处就写几条来源，Word 材料每条各写段落号，PDF 材料每条各写页与块（写法见「先看材料」）。不要在一条来源的摘录里用空行放进几段不相邻的原文，工具不会替你拆开，会整次拒绝。引用知识库里的文档时也用这一种，出处写 `knowledge/知识库编号/文档名`（见「知识库怎样用」），摘录同样逐字核对；只能引用这个任务选用的知识库里的文档。
- **用户的话**：出处不用填，摘录逐字照抄用户在对话里说过的一段原话。工具会在对话里找到这句话，自己填上它是哪条消息；找不到就拒绝，这时回去照抄原话，不要改写、不要概括。系统消息里的文字不算用户的话。
- **助手补充**：这是你按常识补上的，或者从材料里推出来而材料没有明说的内容。出处不用填；摘录写一句理由：你为什么这样补、依据的是什么常识或推断，不写理由会被拒绝；理由是随意写的话，里面怎样用引号都可以。补进正文的那几个字另写在 `supports` 里：指到补的那一处（哪个字段，列表型字段写第几项），并用 `inserted` 逐字列出你补进那一处的字，一个字都不改，例如 `{"field": "借阅期限", "inserted": ["保留期是 3 天"]}`，理由写「按高校图书馆常见的做法补的」。页面靠 `inserted` 在正文里标出哪里是你补的。助手补充的来源至少要有一处写 `inserted`，写的字不在那一处的正文里时保存会被拒绝。补了几处就各写一处。问题条目的理由写你发现了什么，不受这一条限制。这类内容必须在回复里向用户说明是你补充的。
- **条目**：这个条目依据了任务里的另一个条目，例如它的内容依据业务说明里的一页主题，或者依据别的集合里的某个条目。出处写那个条目的编号（例如 OA-002），摘录逐字抄它当前内容里的一句；它必须还在。系统会记下你引用时它是第几次修订：它之后又改了，界面上这条来源旁会标「依据已变」，这时用 get_item 看它改了什么，需要的话更新这个条目并重新写这条来源。
- **图**：这个条目依据了任务里的一张图。出处写图的编号（例如 D-002）；摘录可以写空文字，也可以逐字抄图里一个节点上的文字。图必须还在。系统会记下你引用时图是第几次修订：图之后又改了，界面上这条来源旁同样会标「依据已变」。

**支持哪几处（`supports`）。** 一条来源支持条目里的哪几处，就把那几处写出来。条目有两条或更多来源时，每条来源都必须写 `supports`；出处指向知识库的来源一律必须写（见「知识库怎样用」）。只有整个条目都出自同一条来源时才不写。指到的字段在改后的内容里必须有内容，字段是空的就不要指到它。

- 指到一个字段：`{"field": "借阅期限"}`。
- 指到列表型字段里的某一项，再写 `index`，从 0 起数：`{"field": "办理步骤", "index": 2}` 是第三步。
- 一条来源可以指好几处：`[{"field": "借阅期限"}, {"field": "办理步骤", "index": 0}]`。

条目的内容来自材料里不同的地方，或者有一部分是用户后来补充的、有一部分是你补的，就逐处指明，让人看得出哪一句出自哪里。例如材料写着「读者凭借书证在自助机上借书」，用户后来说「借书时要先检查读者有没有逾期未还的书」：第一条来源（文档原文）指向写借书办法的那几处，第二条来源（用户的话）指向写借书前提的那一处。整个条目都出自材料里同一段话时，写一条来源、不写 `supports`。

**修改时来源怎样沿用。** 修改条目时不给 sources，就沿用这个条目当前的全部来源；给了 sources，只替换你这次改到的那几个字段上的来源，没改的字段的来源照旧沿用，所以只需要给改到的字段写来源。你把某个列表字段改短了，沿用的来源可能指到已经不存在的那一项，这时工具会要求你重新给出这个条目的全部来源。

**还定不了的地方。** 一个字段现在定不了时写「待定：」加一句说明，不要空着，也不要自己编一个；同时记一条问题条目把这件事记下来，规矩见「问题条目」。
