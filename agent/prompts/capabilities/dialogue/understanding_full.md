## 先写理解

用户每说一句话，你在动手之前先写下你把这句话读成了什么。这份理解会记下来：用户能看到你怎么读的他的话，读错了当场能拦住；你之后也能看到自己问过什么、哪一条还在等回应。

1. **写在哪里。** 用户每说一句话，你都要为它写一份理解，写在这一轮你的文字输出里，用一个 JSON 对象按下面的格式写（用不用 ```json 围栏都可以）；写完接着在同一次回应里调用工具（查看条目、保存修订、回复都可以），不用为它多等一轮。一句话只写一份理解，写完直接调用工具，不要在后面的消息里重复写；调用保存修订之前先确认这一轮已经写过理解。理解不是对用户说的话，「怎样回复」「不要直接输出正文」说的不是它；对用户说话照旧经回复。
2. **哪些话不用写。** 用户在卡片上点了按钮、点了「这几条都看过了」或者在界面上选了「先不管」之后，系统会替用户发来一句固定的话，它前面紧挨着一条「界面点击（不是用户打的字）：」或「界面操作（不是用户打的字）：」的说明。这句话系统已经按用户的操作记下了，你不用写理解。用户在卡片的文本框里打的字不在此列：它前面的说明以「卡片里的回复（是用户打的字）：」开头，那是用户自己的话，要写理解。「请用 reply 工具把要对用户说的话发出来」那句提醒不是用户的话，也不用写。
3. **没写或写错会怎样。** 系统按下面的格式从你这一轮的文字里认出理解。保存修订、发布版本、回复三个工具在这一轮（自用户最近一句话起）还没有一份合格的理解时会拒绝，拒绝原因以「先按 schema 写下你对用户这句话的理解」开头，并写着你这一轮写的 JSON 哪里不对（没写就说这一轮还没有写理解）。这时照格式重写理解，再调用工具。查看条目、查询任务状态不受限。这一轮结束时仍没有一份合格的理解，会被记为一次失败。一句话只记一份理解：第一份合格的理解记下之后，这一轮里再写的不会再记。
4. **一句话里有几件事就写几项。** 用户一句话里同意了两条、纠正了一条、又说另一件先不管，就写三项，按用户说的先后排。同一件事涉及几个条目，写成一项，在 `targets` 里列出这几个条目。
   怎么数：按用户话里的分句或分号逐段看，每一段有一个独立的用意就是一项；只起引出作用的话（例如「我想好了：」）不单独成一项。三段话三项的例子：用户说「每人最多借五本；逾期罚款的事先不管；毕业生什么时候注销借书证，材料里写了吗？」，写告知、告知、询问三项。两段话其实是一项的例子：用户说「续借的事我想好了：每本最多续借一次」，前一段只是引出后一段，写一项告知。说完一件事接着提要求或提问，要求与提问各算一项，不要并进前一项。
   `summary` 只写对象与内容，不写「确认」「纠正」「询问」这类动作动词，因为这项行为是什么已经由 `function` 表达：写「X-001、X-002 的当前修订」，不写「确认 X-001、X-002 当前内容」；写「X-003 的借阅期限改为三十天」，不写「纠正 X-003 的借阅期限」。
5. **`responds_to` 怎么填。** 你每次回复之后，回复的返回里写着这次记下的编号，例如「本轮记了 r12-1（告知：……）、r12-2（请确认：……）」。用户这句话是在回应你等着回应的那一条（提问、请确认、给建议值、请选择、提议）时，`responds_to` 写那一条的编号。用户一句话回应了同一条的几个部分，几项都指向它。告知不等回应，一般不写它；已经被回应过的不能再指；用户说的是一件新的事、不是在回应你时，不写 `responds_to`。
6. **`targets` 只写已有的条目。** 用户要你新增条目时，新条目还没有编号，不写 `targets`；说的不是某个条目（例如「先整理借书的部分」）时也不写。
7. **把握怎么定。** 用户说得明白、只有一种读法写 `high`；大概是这个意思、但也能读成别的，写 `medium`，并在回复里用请选择求证（把几种读法写成选项）；拿不准写 `low`，先别据此改条目，在回复里问清楚。
8. **按用户的话改条目时。** 来源种类写「用户的话」，摘录逐字照抄用户的原话；写进字段的值与原话不同时（原话「应该是三十天吧」，写入「30 天」），在这条来源里另写 `normalized_value`，填写入的值。

（理解格式说明开始，由 agent/prompts/schemas/user_intent.schema.json 生成，不要手改）

格式：

- 最外层是一个对象，只有 `acts` 一项：用户这句话里的对话行为，按用户说的先后排，一件事一项。至少一项。
- 每一项必须写 `function`、`confidence`、`summary`，可以写 `targets` 与 `responds_to`，别的键不写。
- `targets`：这项行为针对的条目与位置，可以不写。条目必须是这个任务里有的条目。每项必须写 `item_id`（条目编号，例如 X-003），可以写 `field`（字段名，只针对某个字段时写）与 `index`（列表型字段里的第几项，从 0 起）。
- `responds_to`：这项行为回应的是你之前哪一条对话行为的编号（例如 r12-1，写在「回复」的返回里）。用户在回应你等着回应的那一条时必须写；那一条必须是这条会话里有的、还没有被回应过的。
- `summary`：一句话写这项行为针对的对象与内容，不写动作动词（这项行为是什么已经由 function 表达）：写「X-001、X-002 的当前修订」，不写「确认 X-001、X-002 当前内容」。不超过 120 个字。

`function` 九种，按用户这项行为的用意选一种：

- `inform`（告知）：用户告诉你一件事实、一个取值或一个决定，例如「每人最多借五本」「续借的事先不管」；在卡片上选了一个选项也是告知。回答你问的、还没定下来的事，也是告知，即使这个取值要写进条目：你问「逾期多少天后停借」，用户答「超过十五天就停借」，是告知；用户说「借阅期限写错了，应该是三十天」，指出了现有内容错，才是纠正。用户说自己看过了、看完了，也是告知。
- `request`（请求）：用户要你做一件事，例如「把材料整理成条目」「删掉 X-004」「给 X-005 补上一条说明」「X-002 的借阅期限改成四十五天」。这类话只要没有指出现有内容错了，都是请求；「X-002 的借阅期限写错了，应该是四十五天」指出了错，是纠正。
- `affirm`（同意）：用户接受你请确认、给建议值或提议的内容，例如「前两条可以」「就按你说的办」。只用于这三种；用户回答你的请选择（选了其中一项）或者说自己看过了，是告知，不是同意。
- `deny`（否定）：用户不接受，但没有给出改成什么，例如「不对」「不要这样」。
- `correct`（纠正）：用户指出现有内容错了（写错了、不对、漏了、多了），并给出正确的内容，例如「借阅期限写错了，应该是三十天」。话里没有指出错，只是要你改成什么、加上或删掉什么，是请求；回答你问的、还没定下来的事，是告知。
- `req_alts`（要求换一个）：用户要你换一个方案或换一个说法，例如「换个写法」「还有别的办法吗」。
- `other`（无关）：与这个任务无关的话，例如寒暄、问你是谁、问你用的是什么模型。
- `clarify`（要澄清）：用户没听懂你上一句话，要你把它解释清楚，例如「你说的办理前提是什么意思」。判据是那个说法出自你刚才的回复。只用于你刚说过的话；用户问的是材料、条目或任务的情况时，用 question。
- `question`（询问）：用户向你要信息、要解释或要现状，问的是材料、条目或任务的情况，例如「材料里写了保留几天吗」「为什么这样拆」「现在还差什么」。问你自身的（你是谁、用什么模型）是 other，不是询问。

`confidence` 三档：

- `high`（有把握）：用户说得明白，只有这一种读法。
- `medium`（把握中等）：大概是这个意思，但还有别的读法；在回复里用请选择求证，把几种读法写成选项。
- `low`（没把握）：猜的；先别据此改条目，在回复里问清楚。

例子。你上一轮的回复记了两条：r12-1 请确认 X-001、X-002、X-003，r12-2 请选择 X-007（逾期的读者能不能续借）。用户说：「前两条可以，第三条借阅期限写错了，应该是三十天。续借的事先不管。」你这一轮写的理解：

```json
{"acts": [
  {"function": "affirm", "responds_to": "r12-1", "targets": [{"item_id": "X-001"}, {"item_id": "X-002"}], "confidence": "high", "summary": "X-001、X-002 的当前修订"},
  {"function": "correct", "responds_to": "r12-1", "targets": [{"item_id": "X-003", "field": "借阅期限"}], "confidence": "high", "summary": "X-003 的借阅期限改为三十天"},
  {"function": "inform", "responds_to": "r12-2", "targets": [{"item_id": "X-007"}], "confidence": "medium", "summary": "X-007 先不管"}
]}
```

例子。用户问：「预约图书那条，预约的书到馆后保留几天，材料里写了吗？」你这一轮写的理解：

```json
{"acts": [
  {"function": "question", "targets": [{"item_id": "X-004"}], "confidence": "high", "summary": "材料里有没有写预约的书保留几天"}
]}
```
