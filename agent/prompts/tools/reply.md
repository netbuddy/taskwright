# 工具：回复（reply）

登记工具时读入（agent/src/tools/reply.ts）。正文每一段是一整行：发给模型的文字里没有换行。

## `reply.description`

用途：工具的总说明，登记工具时交给 pi，随工具清单发给模型。

把你要对用户说的话发给用户。你对用户说的每一句话都要经这个工具发出，不要直接输出正文（你按平台说明「先写理解」一节在文字里写的那份理解不是正文）。这个工具是你本次回应的最后一步：要单独调用它，不要与其他工具在同一轮里一起调用，也不要连着调用两次；调用之后不要再输出任何正文。一次回复由告知与一段成文的话组成；只有需要用户回应时，再加一个向用户要回应的行为（提问、请确认、给建议值、请选择、提议之一）。它只核对形式与条目是否存在，不评判内容；形式不对时它会逐条告诉你哪里不对，请照着改好再调用。

## `reply.snippet`

用途：pi 的 promptSnippet：工具清单里这个工具的一句话。

把要对用户说的话发给用户，本次回应的最后一步，单独调用

## `reply.guideline.1`

用途：pi 的 promptGuidelines 第 1 条：这个工具的用法要点。

对用户说的每一句话都经 reply 发出；reply 要单独调用，不与其他工具同一轮，调用之后不再输出正文。

## `reply.param.informs`

用途：参数 informs 的说明，随参数结构发给模型。

零到多条告知，每条是 { text, items }。告知里说到某个条目时在 items 里点名它，界面会画成链接；告知不等用户回应。必须写；没有要告知的事写空列表。

## `reply.param.informs.text`

用途：参数 informs.text 的说明，随参数结构发给模型。

一句完整的话，只写事实（例如你刚保存了什么、材料里写了什么）。必须写。

## `reply.param.informs.items`

用途：参数 informs.items 的说明，随参数结构发给模型。

告知里说到某个条目时在这里点名它，每项写条目编号与它当前所在的修订号，界面会画成链接；没说到条目就不写。

## `reply.param.act`

用途：参数 act 的说明，随参数结构发给模型。

向用户要的回应。只在你等用户回应时填：没有它你下一步做不了或不该做。回答用户的问题、汇报你做了什么，都不填，写 null。回答了问题之后，如果还缺信息要问、要用户做决定、或你补了内容要用户看，照样填。填的话，text 写要用户回应的那句话，不是你的答案。必须写这一项，不填时写 null。

## `reply.param.act.kind`

用途：参数 act.kind 的说明，随参数结构发给模型。

向用户要的回应是哪一种，只能是五者之一：ask 是提问，confirm 是请用户确认某几个条目当前的内容，suggest 是给一个建议值，choose 是请用户从几个选项里选一个，propose 是提议下一步怎么做。必须写。是非题用 choose（把答案写成选项）、征求同意或下一步怎么做用 propose、ask 只给用户要自己说出内容的开放问题。

## `reply.param.act.text`

用途：参数 act.text 的说明，随参数结构发给模型。

要用户回应的那句话：你的问题、请用户确认的话、建议或提议，一句完整的话，不是你的答案。必须写。

## `reply.param.act.items`

用途：参数 act.items 的说明，随参数结构发给模型。

关联的条目或问题条目，每项写条目编号与它当前所在的修订号。提问（ask）、请确认（confirm）、给建议值（suggest）、提议（propose）必须写；提问、给建议值、提议与任何条目都无关时不写它，改写 scope: "general"。请选择（choose）可以不写。

## `reply.param.act.scope`

用途：参数 act.scope 的说明，随参数结构发给模型。

只用于提问（ask）、给建议值（suggest）、提议（propose）三种；请选择（choose）与请确认（confirm）不写 scope。取值只有 general：表示这一问、这条建议或提议与任何条目都无关，这时 items 不写。

## `reply.param.act.options`

用途：参数 act.options 的说明，随参数结构发给模型。

只有请选择（choose）写：至少两个选项，每项是 { key, text }，key 不能重复。

## `reply.param.act.value`

用途：参数 act.value 的说明，随参数结构发给模型。

只有给建议值（suggest）写，而且必须写：你建议的那个值。

## `reply.param.act.resends`

用途：参数 act.resends 的说明，随参数结构发给模型。

只有提问（ask）与请选择（choose）可以写，只在重发时写：这张卡片是把先前一张用户没有答的卡片再问一遍时，写那一张的行为编号（例如 r3-2，查询任务状态「这一段还开着的提问与请选择」一行里列着）。写了之后原来那张不再等回应。问的是新的事不写。

## `reply.param.act.basis`

用途：参数 act.basis 的说明，随参数结构发给模型。

只有给建议值（suggest）写，而且必须写：建议的依据，至少一条。kind 是「文档原文」「用户的话」「助手补充」「条目」「图」之一，locator 是出处，excerpt 是摘录的原文。依据与「保存修订」的来源同一个写法、同一套逐字核对：文档原文写材料路径（Word 材料写段落号），用户的话不写 locator（工具在对话里找到那句话并代填），条目写所依据的那个条目的编号，图写所依据的那张图的编号，助手补充不写 locator、excerpt 写理由。

## `reply.param.act.preview`

用途：参数 act.preview 的说明，随参数结构发给模型。

只有提议（propose）写：这个提议做下去之后条目会怎样变，每项是 { effect, text }，effect 是 remove、add、change 之一。做下去会改动条目时写，撤掉或大改时必须写。

## `reply.param.text`

用途：参数 text 的说明，随参数结构发给模型。

给用户读的成文的话：把告知与向用户要的回应（有的话）连成一段自然的话。必须写，不能是空白。

## `reply.param.activity_done`

用途：参数 activity_done 的说明，随参数结构发给模型。

只在本会话的工作项是单项活动（不在工作流程里）、这项活动做够了、你要汇报做完时写 true：回复下面会多一行「助手汇报：某项活动做完了」，工作项照旧留着。别的时候不写。本会话的工作项是工作流程时写了会被拒绝：流程里做完一段，用进入下一段的请选择卡片提议。

## `reply.param.item_ref.item_id`

用途：参数里条目引用（informs.items 与 act.items 的每一项）的 item_id 的说明，随参数结构发给模型。

条目编号，例如 CON-004。必须写。

## `reply.param.item_ref.revision_no`

用途：参数里条目引用（informs.items 与 act.items 的每一项）的 revision_no 的说明，随参数结构发给模型。

这个条目当前所在的修订号（「UC-001 现在是修订 N」里的 N）。必须写。
