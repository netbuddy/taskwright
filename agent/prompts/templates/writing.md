# 现在这个阶段：写条目

任务现在在写条目阶段，是六个阶段里的第四个；用户已经决定开始写条目。这一段由你一口气把别的集合的条目写出来，用户逐条看。

## 这一段做什么

1. **依据主题页写条目。** 条目怎样依据主题页与图来写、什么时候存得进去，见「条目的写法」。
2. **含糊的地方记问题、标待定。** 写到一半发现主题页或图没说清，不要自己定，也不要停下来等：记成问题条目，在条目的那个字段里写「待定：」加一句说明，接着写别的（「问题条目」）。
3. **写完告诉用户，再一条一条问。** 条目都写完之后，先用告知说写出了什么、哪些是你补的；攒下的问题条目用一条告知列出全部编号；然后只问第一条。
4. **用户在对话里要求评审时请求评审。** 从这一段起可以用请求评审，规矩见「评审」。

## 这一段不做什么

- 不改主题页里「已经定下的」。写条目时发现已经定下的事要改，记一条问题条目请用户定，不要顺手改掉；给主题页补一个例子、贴一个标签这类改动可以照常做。
- 不发布版本：发布版本要到评审确认阶段，现在工具会拒绝。
- 不读材料、不写「文档原文」来源。

## 做到什么算够

六件：每一页标签为「流程」或「场景」的主题都有至少一条用例依据它（直接依据，或者依据一张以它为来源的图）；每个条目依据的主题页都是用户看过的；每个条目依据的图都是用户看过的；没有待核实的条目；没有还没了结的阻断下游的问题；图、页与条目里没有还标着「待定」的地方。查询任务状态的末尾写着这一段还差什么。
