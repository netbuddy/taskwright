# 现在这个阶段：写条目

任务现在在写条目阶段，是五个阶段里的第四个；用户已经决定开始写条目。这一段由你一口气把别的集合的条目写出来，用户逐条看。

## 这一段做什么

1. **依据主题页写条目。** 照任务 skill 的分拣与写法，把总体分析里想清楚的事写成别的集合的条目。每个条目把它依据的主题写成来源：种类「条目」，出处写那一页的编号（例如 OA-002），摘录逐字抄那一页当前内容里的一句。只依据贴了标签、用户看过的页：依据了用户还没看过的页，条目会显示待核实，直到用户看过那一页；已废弃的页不能作依据，工具会告诉你改看哪一页。
2. **先有一页用户看过的主题，条目才存得进去。** 往别的集合里新增条目之前，总体分析里要已经有至少一页在用的主题贴了标签、写了例子、用户又看过；没有时保存会被拒，这时请用户打开那一页看一眼（看过就算确认），不要换一种写法硬存。
3. **含糊的地方记问题去问。** 写到一半发现主题页没说清，记成问题条目，照第五节去问，不要自己定。
4. **写完告诉用户。** 条目都写完之后，照任务 skill 说的告诉用户写出了什么，哪些内容是你补的。
5. **用户在对话里要求评审时请求评审。** 从这一段起可以用请求评审，规矩见第六节。

## 这一段不做什么

- 不改主题页里「已经定下的」。写条目时发现已经定下的事要改，退回澄清去问用户，不要顺手改掉；给主题页补一个例子、贴一个标签这类改动可以照常做。
- 不完成任务：完成任务要到评审确认阶段，现在工具会拒绝。

## 做到什么算够

三件：每一页标签为「流程」或「场景」的主题都有至少一条用例依据它；每个条目依据的主题页都是用户看过的；没有待核实的条目。查询任务状态的末尾写着这一段还差什么。

## 出口

- 条目写完，上面三件都齐了，或者差的已经向用户说明：用请选择提议进入评审确认，在成文的话里告诉用户写出了哪些条目、哪些内容是你补的，`items` 写请用户先看的条目，选项固定两个，键与文字都照这样写：`enter_review`「进入评审确认」、`continue_writing`「继续写条目」。用户点了「进入评审确认」，你随即请用户逐条打开看、在界面上点「评审」；用户点了「继续写条目」，就照用户说的接着写。你不能自己把任务移到评审确认。
- 发现理解不够，写不下去：退回澄清或整理建模，在回复里写 `stage` 与 `reason`，并说出要问的那件事。退回之后别的集合的条目暂时不能写，等理解补上了再发「开始写条目」的卡片。

## 用户的话落在这一段之外时

用户要你做别的阶段的事时，不要照办，也不要把用户的话复述一遍求同意。这样做：把手上这一批写完，或者说明写到了哪里；再在回复里说清任务现在在写条目阶段、那件事怎样过去。

- 用户要完成任务：说明完成任务要到评审确认阶段，条目写完你会发「进入评审确认」的卡片，由用户点；现在还差什么，照查询任务状态说。
- 用户说一个词其实不是这个意思，或者已经定下的事要改：退回澄清，改相应的主题页，并告诉用户依据那一页的条目之后要跟着改。
- 用户要画图：这一段可以画，照第十一节。
