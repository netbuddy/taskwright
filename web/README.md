# web：任务型智能体的前端骨架

三页：任务列表页、任务页、工作视图。技术栈是 React、Ant Design、Ant Design X，用 Vite 开发与构建，接口照接口约定（docs/api.md），以及与后端对齐之后的几处补充（见本文末尾）。

## 目录

| 路径 | 是什么 |
|---|---|
| `src/api/types.ts` | 接口类型，字段名与约定逐字一致。 |
| `src/api/client.ts` | 全部 HTTP 请求都经这里发出；错误统一成 `ApiError`。组件不直接调用 fetch。 |
| `src/api/events.ts` | 事件流（SSE）的读取与解析。用 fetch 读流，重连时自己带上 `Last-Event-ID`；45 秒收不到任何东西就主动重连。 |
| `src/state/workState.ts` | 工作视图的状态与事件应用规则，是纯函数，测试直接调用。 |
| `src/state/useWorkView.ts` | 工作视图的数据来源：先连事件流，再读整份数据，之后只听事件；收到 `resync` 或发现序号缺口时重读一次整份数据。 |
| `src/pages/` | 三页。 |
| `src/components/` | 外壳、新建任务、生成文档、完成条件；`work/` 下是工作视图的对话区、卡片、条目区、条目详情、确认已失效的差异、文档区。 |
| `src/model/` | 由数据算出的状态（评审、确认、筛选）、列表字段按步骤对齐的比对、时间与数字的写法。 |
| `src/test/` | 组件测试（Vitest）。 |

## 怎样起

```bash
cd web
npm install

# 在代码仓根目录：后端与开发服务器一起起，Ctrl+C 两个都停
scripts/dev.sh                      # 后端 8790（被占时往后找空端口），开发服务器 5680，/api 代理到后端
scripts/dev.sh --demo               # 同上，但后端用假模型、数据放临时目录，并建好一个带示例材料与几个条目的演示任务

# 只起开发服务器，接一个已经在跑的后端
TASKWRIGHT_WEB_PORT=5682 TASKWRIGHT_API_TARGET=http://127.0.0.1:8791 npm run dev
```

开发服务器绑 `0.0.0.0`，端口与代理目标都由环境变量给（`TASKWRIGHT_WEB_PORT`、`TASKWRIGHT_API_TARGET`）。不给 `TASKWRIGHT_API_TARGET` 时代理到本机的 `http://127.0.0.1:8790`，与 `scripts/dev.sh` 起后端的缺省端口相同；那里没有后端时，页面显示「请求没有成功（HTTP 502）」。

`--demo` 不需要模型服务，也不需要密钥，但和真后端一样要 PATH 上有 pi。假模型按 `examples/library-lending/fake-model.json` 回答：第一句话之后把示例材料整理成 3 个功能用例、1 条非功能需求和 1 个待澄清的问题，之后每句话都隔 10 秒才回答。演示数据放在临时目录里，退出时删掉。

经开发服务器的代理上传超过上限（5 MB）的文件时，可能看到 HTTP 502 而不是后端的 413：代理转发时要求后端应答后关连接，后端不读过大的请求体、回了 413 就关连接，代理这时还在往里写请求体，写不进去就自己回 502。页面在发送之前已按服务信息接口给的上限拦下过大的文件，平时走不到这一步；只有绕过页面（例如用 curl 经代理上传）才会遇到。后端自己出页面（`--web`，桌面包与服务器部署都是这样）或直连后端时，浏览器收到的是 413 与「单个文件不能超过 5 MB。」，不受影响。

几种不容易碰到的情形，用真后端这样复现（后端没有为它们准备专门的开关）：

- **助手正在另一条会话里工作。** 用 `scripts/dev.sh --demo` 起，在演示任务的会话里再说一句话（演示用的假模型隔 10 秒才回答），这 10 秒里新建或打开另一条会话，在那里说话或改条目：发送与写入按钮变灰，接口返回 `session_busy`。
- **事件流断开后重连并补发。** 只重启后端、不动开发服务器：另开一个终端，用与原来相同的 `--tasks`、`--runs` 和端口起后端（`scripts/dev.sh` 起的后端先按进程号停掉）。已建立的事件流随之断开，页面每隔一两秒重连一次，重连请求带着 `Last-Event-ID`，后端回来后补发缺的事件。浏览器开发者工具里的「离线」模拟不会断开已经建立的事件流，用它看不到重连。
- **缺口太大、要求重新同步（`resync`）。** 在上一条的「后端停着」那一段里，用造数夹具往这个任务的库里写 500 条以上的事件：`node agent/tests/fixtures/seed_compare_task.mts many-events <任务目录> <条目编号> <修订号> 510`（例如演示任务的 `UC-001` 与修订 `1`）。再起后端，页面带着旧的 `Last-Event-ID` 重连，缺口超过补发窗口，后端发 `resync`，页面随即重读整份数据。

## 几条写法约定

- **随任务定义变化的文字一律从接口取，不写死。** 这类文字包括集合名、字段名、枚举取值、完成条件名、任务类型。「先不管」按钮按取值「用户决定保留」认出它适用的集合，不按字段名认。
- **界面上的状态变化只来自事件流。** 说话、直接操作的响应只当作「接受了还是拒绝了」：接受时登记「正在保存」，等库事件到了才改界面；拒绝时就地显示原因。不做乐观更新。
- **发给执行者的话只用接口约定的固定模板**，常量在 `src/components/work/ReplyCard.tsx` 的 `TEMPLATES` 里。

## 已与后端对上的几处补充

- 说话、直接操作、停下、往前读对话这四个请求，都在路径后面带 `?session={session_id}`。
- 卡片点击时，说话的请求体多带两项：`origin: "card_choice"`，以及 `card: { reply_message_id, kind, choice }`。
- 快照里 `conversation.messages` 的每一条都有 `type` 字段。
- `user_message` 带 `client_id`；`ui_action_noted` 带 `revision_no` 与 `op_id`；`confirmation_recorded` 带 `op_id`。
- 库事件的操作种类多了 `restore`，表示撤销了一次删除。
- 新增错误码 `not_found`，新增接口 `GET /api/v1/task-types`。
- 成功响应都带 `ok: true`；列表类接口的内容放在一个键下，例如 `{ok, tasks}`、`{ok, sessions}`、`{ok, versions}`。
