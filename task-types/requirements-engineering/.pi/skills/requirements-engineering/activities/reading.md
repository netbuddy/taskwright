## 这类任务在核读材料阶段

**这类任务的核读按分析提纲做，在平台说明的第一遍之前先做第 0 遍「定骨架」。** 分析提纲是 `.pi/skills/requirements-engineering/outline.md`：八个分析维度，每个维度下若干提纲条目，每个提纲条目是一个要回答的问题。核读开始先用 read 把它读一遍。第 0 遍做完要停下来请用户确认骨架；这一处与平台说明「这一段由你一口气做完」不同，以这里为准：问完就结束这一轮回复，不得自动续读，等用户在对话里答复。

**第 0 遍：定骨架。** 依次做下面四件事：
1. **快读，认出子系统。** 每份材料只看结构，不读全文：Word 与 PDF 材料看分段清单里各块的标题，再用 read 带 offset 与 limit 读开头二三十行（标题、目录、首段）；.md 与 .txt 材料用 grep 搜 `^#` 看小标题，再读开头二三十行。由此认出这件事分成哪几个子系统：一个子系统有自己的用户、流程与业务对象。材料讲的是一个平台加上面的几个应用时，平台本身各应用共用的部分算一个子系统，其余每个应用各算一个；材料不分子系统时，整件事就是一个子系统。子系统的名字照材料里的叫法。同时记下每份材料主要讲哪个子系统（讲共用部分或者讲全局的，记为全局）。
2. **立维度页。** 八个分析维度各立一页，作为顶层：标题就是维度名，一字不改；「上级主题」不写；标签用提纲里这个维度的 `tags`；「它是什么」第一行写「待定：读材料后填写。」，下面逐行列出这个维度各提纲条目的问题；「例子」写一条「待定：读材料后补具体情形。」；来源种类「助手补充」，理由写「按分析提纲立的维度页，内容待材料填写」，`inserted` 写「它是什么」的第一行。另立一页「未归类的发现」作为顶层，标签「范围」，「它是什么」写「待定：挂不上任何提纲条目的事实先记在这里，第二遍逐条处理。」，例子与来源照维度页的写法。
3. **立子系统页。** 提纲里标了 `per_unit: true` 的维度，在维度页下为每个子系统各立一页：标题「维度名 · 子系统名」，「上级主题」写那一页维度页，标签、「它是什么」、例子与来源照维度页的写法。`per_unit: false` 的维度不立子系统页。
4. **预开候选。** 用你对这类系统的了解，为每个子系统在乘子系统的维度下预先开出候选：同类系统通常有、这个子系统很可能也有的流程、角色或业务对象。每个维度每个子系统最多三个，只开最有把握的，没有把握就不开。候选立成页，挂在对应的子系统页下：标题以「候选：」开头，例如「候选：报修单派工」；「它是什么」写「候选，待材料证实。」，再写一句为什么同类系统通常有它；标签照维度；例子写一条你推断的情景；来源种类「助手补充」，理由写明是领域常识、待材料证实。候选是要去材料里核实的问题，不是事实，不写「已经定下的」。

一次保存最多写 4 页，存好一批接着存下一批，第 0 遍的页全部立完再停下。这一遍不记问题条目，不读材料全文。

**骨架确认（必停）。** 第 0 遍的页全部立完，回复里依次写三样，然后结束这一轮：
- 一段缩进清单，二十五行以内：第一行列子系统，每个子系统后面括注主要讲它的材料；然后每个维度一行，乘子系统的维度在下面每个子系统缩进一行，行末写这里开的候选名（没有就不写）。
- 一句话告诉用户：可以在「业务说明」页签里直接删页、改标题、补页。
- 一句话说这次的主导方式默认是「协作」：材料没写的地方由你从材料与常识出候选，请用户定；用户也可以选「用户主导」（你只按提纲提问，材料没写的直接问用户，不出候选）或「助手主导」（你只在几处必停的地方请用户确认）。
最后只问一个问题：照这个骨架读，还是先改一改？不要再问别的，不要列选项菜单，不要发进入下一步的卡片。

**用户答复之后。** 用户说照这个骨架读，就开始第一遍；用户同时说了主导方式，就照它办，没说就是协作。用户说要先改，就回一句「改好了告诉我」并结束这一轮；用户说改好了，先用查看条目把维度页、子系统页与候选页重看一遍（用户可能删了页、改了标题、补了页），以用户改后的为准，再开始第一遍。

**第一遍每种页回答什么。** 每一块怎样填见上文第 4 条；「它是什么」按页的种类回答下面这些问题，每组问题一段（角色页与流程页一般两到四段）。材料写了的逐字引作来源；材料没写的那一处写「待定：」加一句说明，并记一条种类为缺失的问题条目。
- 角色：是谁（哪个部门、多少人、什么班次）；做什么；每天面对多少量；痛点是什么；与目标系统在哪几处接触；谁对它有权。
- 流程：由什么触发；分几步，每一步谁做、用什么系统；哪里有分支与例外；涉及哪些业务对象；受哪些规则约束；有哪些数字（时长、量、门槛）；现状有什么问题。
- 业务对象：指什么；与相近的词差在哪里；关键属性；有哪些状态；与哪些对象关联；量级。
- 目标、范围、假设、决定：要达到什么、怎么衡量；谁定的、什么时候定的、依据哪份材料。
- 材料里的术语定义段落也立成页，标签贴「概念」。

**每页至少有什么。** 每一页至少贴一个标签、写两条例子（反例、例外也算），流程页至少一条以「例外：」开头；少于一个标签或一条例子工具会拒绝。例子没有现成的，写材料里的一个具体情形或反例并给来源；材料里确实没有时，写一条你推断的情景，来源种类写「助手补充」，摘录里写明「推断的情景，用于说明规则」（自动待核实），它不算材料里的事实。标签拿不准就贴最接近的，并在问题条目里记一句为什么拿不准。

**分批。** 一次保存最多写 4 页主题，看到这一批保存成功之后再保存下一批，接着读，不停下来等用户。这几批里不要夹着用例、需求或约束：这个阶段它们存不进去。问题条目可以与页同批保存，也可以单独一批。

**第二遍各样东西记成什么。** 照平台说明「对照与洞察」做，落到这些地方：
- 两处说法不同而仍未决的：问题条目，种类「冲突」，来源写两边原话。已被裁决改掉的：写进那一页的「已经定下的」，并在「它是什么」里写明旧的说法出自哪份材料、被哪一条裁决改掉。
- 缺口：问题条目，种类「缺失」，页里那一处留着「待定：」。
- 没有人确认过的前提：立一页，标签「假设」，「它是什么」写明你从哪里看出这是个前提、它不成立会怎样，来源种类「助手补充」。
- 同一个东西几种叫法：合成一页，别的叫法写进「别名」；同一个叫法指不同东西：分页，在「它是什么」里写清差别。
- 领域参照：材料没覆盖、对这个系统要紧的，立一页标签「假设」，或者记一条种类为「缺失」的问题条目；来源种类「助手补充」，摘录写明是领域常识。照分析提纲 `.pi/skills/requirements-engineering/outline.md` 里「风险、假设与运维」这一维度的七个问题逐项问（每项只是一个问题，不是答案），一般不超过八条，按最影响别的事排先后。

**总体观察。** 第二遍做完，在「概述与范围」这一章写一页：标题固定为「总体观察」，标签「范围」，「导语所属章」不填（它不是导语页）。「它是什么」列最值得用户先看的三到五条观察（两处说法不同、缺口、领域参照里最要紧的），按最影响别的事排先后，每条一句话，带它引用的页或问题条目的编号。「例子」写两条：最要紧那两条观察各一个具体情形，引材料原话。「已经定下的」不写，除非其中有确实已经定下的事。

## 这一步怎样收尾

- 两遍做完、总体观察写好，先照「做到什么算够」逐份材料汇报处理结果与数字，汇报本身不拦卡片；再提议进入下一步：在成文的话里先用那一小段话说清材料讲的是什么，再说进入下一步之后你要问的第一件事（最影响别的事的那一件；记了阻断下游的问题时，把它们列在最前），`items` 写请用户先看的页，总体观察排第一。
- 第一遍还有材料没读、或者第二遍没做完时不发这张卡片，照「中途停下时」写清做到哪里。
- 材料很少、没有什么可立的时候，同样发这张卡片，在成文的话里说一句「材料只有一小段，我们直接一件一件说」。
- 用户问材料里写了什么、现在读到了哪里，要你接着立页，补一句材料里没有的说明：照做；用户补的话记进相应的主题页，来源写用户的话。
