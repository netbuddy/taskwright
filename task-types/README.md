# task-types 目录

这里放产品自带的任务类型。一种任务类型是一个目录，里面是任务目录的起始文件：任务定义、skill、规矩文档、评审规则与文档模板。

任务服务启动时把这里的每种任务类型播种到数据目录下的 `task-types/`（数据目录里已经有的不覆盖），并记一份 `manifest.json` 与第 1 个修订。
建任务（网页上的「新建任务」，或接口 `POST /api/v1/tasks`）从**数据目录里**那一份整个复制成新的任务目录，再写任务记录；
数据目录里的任务类型可以修订，每个修订存一份完整目录（`backend/src/task_types.ts`、`backend/src/workspace.ts`）。
所以改了这里的文件，已经播种过的数据目录不会自动跟上；这里的这一份只用于播种。

任务类型里**不放** `AGENTS.md`：pi 会把它当作上下文文件追加到系统提示后面，容易把模型带偏。

| 任务类型 | 它是什么任务 |
|---|---|
| `requirements-engineering/` | 需求工程：把需求弄清楚、写成条目、评审确认，并发布需求规格说明。测试也用它。这里不放试验材料，`inputs/` 由建任务时建出。 |
