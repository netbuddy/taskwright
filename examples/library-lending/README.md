# Example: school library lending

`requirements.md` is a short, fictional requirements description (in Chinese, like the bundled task type). It deliberately leaves a few things open, so the agent has something to ask about: holiday loan periods, how fines are paid, what "smart recommendations" means.

See [section 5 of the user guide](../../docs/user-guide.md#5-try-the-example) for how to run `run.sh`, and the rest of the [user guide](../../docs/user-guide.md) for the same flow in the web interface. Installation and model setup are in [docs/deployment.md](../../docs/deployment.md).

`requirements-styled.docx` is a longer version of the same material written as a Word document that uses many Word features (heading levels, lists, merged and nested tables, inline and floating pictures, a text box, notes, fields, a comment and tracked changes). `build_styled_docx.py` generates it together with `requirements-styled.样式清单.md`, a list of every feature used and a numbered list of every paragraph and table cell in `word/document.xml`; run it again after changing the script (it needs python-docx and Pillow, plus LibreOffice and poppler's pdftotext and pdfimages). Word records where each page started when it saves a file (`w:lastRenderedPageBreak`), and the material pane uses these marks to show a Word file page by page; python-docx cannot lay out pages, so the script lets LibreOffice lay the file out and writes the marks back at the start of each page's body text.
