# 用户手册（User guide）

本手册讲服务跑起来之后怎么用（安装与模型接入见[部署](deployment.zh-CN.md)）。先在网页界面里走一遍完整的一个任务，从创建任务到生成文档，再介绍示例脚本、其他操作方式与观测台。用的是随附的任务类型「软件需求规格说明」，以及 `examples/library-lending/` 里的示例材料。想先配着截图一步步走完一个任务，可以从[教程](tutorials/srs-authoring.zh-CN.md)开始。

用 `scripts/dev.sh` 启动后端与网页界面（见 [deployment.zh-CN.md](deployment.zh-CN.md)），打开 `http://localhost:5680`。

## 1 创建任务

界面是中文的；下文按钮名用界面上的中文，括号里是英文名。页面标题是「需求工作台」。

在任务列表页选择**新建任务**（New task），挑选任务类型，给它起个名字（可选择再加一个领域标签），然后点**新建**（Create）。这个对话框不收文件；新建之后会打开新任务的任务页。

任务页是一个任务的总览与入口，自上而下六块。

- **面包屑与任务头**：任务名、状态（进行中是绿底，已完成、已放弃是灰底）、任务类型，右边是**生成文档**（Generate document）与**新建会话**（New session）两个按钮，下面一行写创建时刻与最近一次活动。
- **完成条件**（Completion conditions）：左边是分数，例如「完成条件 1/3」，分母只数现在用得上的条件，分子数其中已经满足的。右边每条完成条件一行：已经满足的前面是绿色的勾；还差的是琥珀色的圈，并写明还差哪几个条目，例如「功能用例的每个条目都要评审通过，UC-001 和 UC-002 还在等评审。」。集合还没有条目、暂时不用核对的条件不逐条列，合成末尾灰色的一行，例如「非功能需求、约束现在还没有条目，它们的完成条件暂时不用核对。」，它们不算进分数。全部满足时整块换成一句「完成条件已全部满足，可以在会话里请助手标记完成。」。
- **交付物**（Deliverable）：每个集合一张卡，写集合名与编号前缀、条目个数和一行「评审通过 N/M · 已读 N/M」。N 只数真正评审通过的条目；有评审不通过但你保留了写法的条目时接着写「 · 已保留写法 K」；不评审的集合只写已读。鼠标停在卡上看详细的说明。还没有条目的集合整张卡是灰的，写「还没有条目。」。标题右边写「最后改在修订 N」。点一张卡进入最近活动的那条会话的工作视图，条目区停在这个集合的页签；任务还没有会话时卡片不能点。每个集合一种颜色，颜色跟着集合名走，只用来区分集合，不表示状态。
- **会话**（Sessions）：每条会话一行，写它的第一句话、最近活动的时刻和这条会话产生了几次修订，最近活动的排在前面，助手正接着的那条行前有一个绿色小圆点。点一行或它右边的**打开**进入那条会话。
- **材料**（Materials）与**选用的知识库**（Knowledge bases in use）：两张并排的卡，窗口窄时上下排。

页头的「最近一次活动」与会话一块在助手做完一轮时自动更新，不用刷新页面。

材料卡列出每份材料的名称、大小与上传时间，每行有**查看**（View）。在这里上传的一律是材料：把文件拖到虚线框里，或者点它选择文件；整理时要参考的文档不在这里传，到知识库页面上传。还没有进入对话的材料另有**删除**（Delete）：材料上传之后任务里还没有任何会话活动过，就可以删除，确认框写「删除之后这份材料就没有了，助手下次开始会话时不会再看到它。」。上传之后一旦有会话说过话，这份材料就进入了对话，不再有「删除」，要换内容只能再上传一份新的。选用的知识库卡列出这个任务选用的知识库和各有几份文档：通用知识库每个任务都会用到，不能去掉；别的知识库可以点**不再选用**；**选用别的知识库**弹出勾选列表，助手只在选用的这几个知识库里查找。

上传收纯文本的 `.md`、`.txt` 文件与 Word 的 `.docx` 文件，单个不超过 5 MB；更大的文件在发送之前就被拦下，提示「单个文件不能超过 5 MB。」；别的类型的文件也在发送之前被拦下，提示「只接受 .md、.txt 与 Word 的 .docx 文件。」。同一个任务里不会有两份内容完全相同的材料，也不会有两份同名的材料：上传的文件与已有的某份材料内容完全相同时，不论文件名，提示「这份文件与已有的材料《……》内容完全相同，没有重复保存。」；文件名与已有的某份材料相同而内容不同时，提示「这个任务里已经有一份叫《……》的材料，内容与这份不同。请给文件换一个名字再上传。」，给文件改个名字再传即可。这两种情况都不保存文件，材料清单不变。判断同名时不区分大小写，也不计文件名首尾的空白；只差全角半角的（例如全角括号与半角括号）算不同的名字。工作视图对话区的**附一份材料**按同样的规则检查。系统还会为 Word 文件生成一份供助手阅读的 Markdown 文本，保留了标题、编号、列表和表格，图片写成链接；清单里不列这份文本，点 Word 文件的**查看**，看到的是按原版式分页显示的 Word 文件本身。个别 Word 文件的版式可能画不出来，这时「查看」和材料页签都显示「这份 Word 文件在这里显示不出来，但文件已经上传好了：助手仍然能读到它的内容，条目的来源仍然有效，不需要重新上传。」：助手读的是那份 Markdown 文本，不受影响；这份文件的来源标签只写文件名和章节，不写页码和页上的位置。新传的材料要到下一次会话开始时智能体才看得到，所以先传材料，再开会话。

一个任务可以有多个会话（对话），它们都在同一份交付物上工作。点**新建会话**（New session）开一个会话，页面随即进入工作视图。智能体在后台启动，对话区顶上一条简短的状态消息（系统说明）会告诉它这个任务目前的样子和有哪些材料。页面上这条说明以「这条会话开始时（时刻）的任务状况：」开头；续接以前的会话、上次之后有变化时，开头是「接着这条会话继续时（时刻），上次之后交付物的变化：」。助手看到的是同一份内容，只是开头与个别说法是写给它的。还没有说过话的会话，在你打开别的会话之后不会保留；再打开它的地址，页面写「找不到这条会话」，并给出回到任务页的链接。助手正在这条会话里工作时不能新建会话，等它做完这一轮再新建。

## 2 与智能体对话

工作视图分三栏：对话区、条目区（交付物，按集合分组）和右侧栏。右侧栏有三个页签：**材料**（Materials，上传的原文）、**文档**（Document，生成文档）、**修订**（Revisions，修订日志，见第 3 节）。任务定义要求时，「材料」之后还多一个页签：需求规格任务里是**领域说明**，按类别分组列出这个任务的领域说明（术语排最前），每条写明与别的条目的联系；还没有和任何条目关联的那条用琥珀色写明，点一条在条目区打开它。材料页签里的 Word 材料，文件名下面有一行「**按章节看引用**」：点开后逐节列出章节标题、段落范围与被几个条目引用，还没有条目引用的一节灰显、写「还没有条目引用这一段」，点一节，原文跳到那一节。在材料原文里选中一段文字，选区上方浮出一条动作条：**据此新建条目**、**补到当前条目**（条目区打开了一个条目时才有）、**就这段提问**。三个动作都是把一句话连同这段原文发给助手，要等它做完；点「就这段提问」，动作条变成输入框，写好问题点**发送**。点别处或按 Esc 键，动作条消失。**收起**（Collapse）把右侧栏收成一条竖边，窗口窄时它默认收起。顶栏的**字号 小 中 大**（Font size）让全站文字变小或变大；文字也会随窗口宽度自动缩放，选择记在浏览器里。

告诉智能体你想要什么，例如「请读 inputs 里的材料，整理成需求规格说明。」它会读材料、写条目、然后回复。每条回复先列出它刚做了什么，再说它需要你做什么。需要你处理时，回复末尾会带一张卡片：

| 卡片 | 问的是什么 | 你的选项 |
|---|---|---|
| 提问（Question） | 一个开放式问题 | 打字回答；如果问题针对的是某些条目，可以点**先不管这条**（Keep pending，仅限「问题」集合里的条目）或**我不知道，你按常识补**（I don't know, fill in from common sense） |
| 选择（Choose） | 从几个答案里选一个 | 点某个选项，或者自己打字回答 |
| 确认（Confirm） | 请你对这些条目现在的内容给一个明确答复（只在智能体确实需要时才用） | **这几条都看过了**（I've read these），把这几条记为已读；或**不对**（Not right，可以附上哪里不对）。每个条目行写着它当前所在的修订和你看过没有，例如「修订 9（已读）」「修订 9（未读）」；看过更早的修订、之后又改过的写「修订 9（已读 · 你看过修订 4，之后又改过）」。 |
| 建议（Suggestion） | 一个带依据的候选值 | **采纳**（Adopt）或**换一个**（Another one） |
| 提议（Proposal） | 一个计划，说明会新增、改动或删除什么 | **就这样做**（Do it）或**不要**（Don't） |

你回答了一个问题条目之后，助手先改它牵涉的条目，再用一张选择卡片问这个问题是否已解决，选项是「已解决」「还没解决，继续改」「先不管，保留」。只有你在卡片上点了「已解决」或「先不管，保留」，这条问题才会被改成已解决或用户决定保留；你打字说解决了，助手也会先发这张卡片请你点。你点了之后，这条问题或它牵涉的条目又被改过，助手要重新问。你自己在条目上点**先不管，保留**照旧直接生效。

任何时候都可以不点按钮、直接打字，不必先回应卡片。如果选项里没有你知道的答案，用自己的话说出来就行。

智能体改完条目只告诉你改了什么，不再请你确认。你确认一个条目的办法是看它：打开它的详情就算（见第 3 节）。问你要不要完成任务之前，智能体会先告诉你还有几条从没看过。完成之前只剩未读挡着时，还没结掉的卡片下面还会提示「还有 N 条未读」，旁边的**筛出来看**把条目列表筛成未读的那几条。

**一次只有一方在改。** 任一时刻只有一方在改交付物：

- **智能体工作期间**，条目区顶部是一条横幅「助手正在工作，结束后你可以继续修改」。条目上的写入按钮（修改、保存、删除、标为已读、先不管、撤销）全部变灰，鼠标停在灰掉的按钮上会说明原因，发送键也变灰：一句话启动它的一次工作，下一句要等这次做完。你仍然可以打字，草稿留在输入框里。**让助手来改这一条**和**回答这个问题**照常可用，因为它们只往输入框里预填文字。这期间经 HTTP 接口发来的说话与直接操作都会被拒绝，错误码是 `session_busy`。打开条目详情照样记为已读，因为它不改交付物。
- **你有未保存的条目编辑时**（编辑框打开，而且内容与打开时不同），发送键与对话区卡片上的按钮变灰，并提示「先保存或取消正在编辑的条目」。保存或取消之后恢复。

网页界面目前还没有停止按钮。要中断智能体，用 HTTP 接口发 `stop` 控制请求（见[接口参考](api.zh-CN.md) 5.5 节），已经保存下来的内容不受影响。这时，这一轮的摘要行「助手做了 N 步，用了 X」下面会多一行琥珀色的说明：「这一轮是你让助手停下的。已经保存的修订 2 保留着；停下时它正在做的那一步没有做完，没有保存。」这一轮保存过几次修订就列出几个修订号，一次也没有保存时写「这一轮还没有保存任何修订」；说明下面的「产生了修订 N」小标签点开就是修订页签里的那几次修订。因为出错停下的一轮写「这一轮因为出错停下了，助手没有做完。已经保存的修订保留着；你可以再说一句，让它接着做。」，右上角同时弹出一条红色提示，简短地说同一件事。刷新页面之后，这一行说明仍在。

一次工作产生了修订时，回复底部会有一枚小标签，例如「产生了修订 8、9」；点它，右侧栏切到修订页签并选中那几次修订。

## 3 处理条目

交付物每保存一次就是一次**修订**，修订号在任务里从 1 起连续编：智能体的每次保存、你的每次直接操作（修改、删除、先不管、撤销）各产生一次。条目没有自己的版本号；条目最近一次在哪次修订里被新增、修改或恢复，就说它「现在是修订 N」。标为已读不产生修订。

每个条目最多挂一枚有色的状态徽标，写「这条现在还缺什么」；同时缺几件时只写排在最前面的一件，先后是：「评审不通过 N 处」（红）、「未读」（琥珀）、「待评审」（灰）、「评审不通过 N 处 · 已保留」（绿边框：你保留了现在的写法，按你的决定算通过）、「问题 N 未解决」（琥珀）。什么都不缺的条目不挂徽标。鼠标停在徽标上可以看到全部状态：评审结论、你最后看过哪次修订、有几个问题没解决。不评审的集合（问题、领域说明）不会出现评审三种。未读的行像未读邮件一样加粗。其余信息是灰色小字：类别、改动过不止一次时的「修订 N」（智能体最近一次工作改过的写「修订 N · 刚改」并加粗）、「有助手补充的内容」；领域说明一类的集合在列表行上另写来源条数，其余集合的来源条数写在条目详情的标题下面。条目详情的标题行用同样的徽标，下面一行灰字写「已读 · 现在是修订 4，由助手写的 · 来源 3 条」。在列表里点一个条目，可以看到每个字段，以及每一部分内容的来源（界面上的来源小标签是下面四种）。**打开详情就记为已读，看过就算确认**，没有确认按钮；只认打开详情这一个动作，在列表里看到不算。已读是按条目算的：看过一次就一直是已读，智能体之后再改它也不会翻回未读。四种来源小标签是：

- **材料原文**（Document excerpt）：从某份材料里逐字摘录的一句话，并标明出自哪个文件；点它，材料页签里会高亮这句原文（摘录是几段拼起来的，就逐段高亮，并滚到第一段）；在材料里一段都找不到时，材料页签顶部提示「没有在材料里找到这段原文」，两秒后消失。Word 材料按原版式分页显示，它的来源标签写的是页、章节和页上的位置，例如「requirements-styled.docx · 第 3 页 · 3.1.1 逾期罚款 · 页下」；章节是被引用的那一段（含）之前最近的标题，自动编号照 Word 里的样子写，例如「第一章 总则」，表格里的标题不算；摘录跨了几个段落时，这几段整段标出，并提示「这段引用跨越了多个段落，已整段标出」。页眉页脚、文本框、脚注尾注里的文字只能看，不能被条目引用；批注不显示，修订按接受后的文字显示；
- **知识库**（Knowledge base）：从任务选用的知识库里某份文档逐字摘录的一句话，标签是紫红色的，出处写「知识库名 / 文档名」（Word 文档再写第几段）；点它，在一个只读的对话框里看那份文档的正文，这句原文高亮。那份文档已经从知识库删除时，来源照旧留着，出处不能点，旁边写「这份文档已经不在知识库里」。知识库里的文档是参考资料，不出现在材料页签里，也不会被整理成条目；
- **用户的话**（Your words）：你在对话里说过的话；
- **助手补充**（Added by the assistant）：智能体推断或补全的内容，并附上理由；
- **领域说明**（Domain note，写成「领域说明 DN-002」）：「领域说明」集合里已经记下的一条解释（领域说明：材料里或你说明过的背景、术语、角色，供条目引用）；点它打开那条领域说明。领域说明的详情里列着「被哪些条目引用」。不评审的集合（问题、领域说明）在条目区与任务页上都不显示评审状态；

助手改条目时，原来的来源默认留着。列表里的每一项按内容认：助手在列表里插入、删除别的项或调换先后之后，来源仍指着原来那句话；删掉的那一项，指到它的来源随之去掉。某一项或某个字段被助手改写之后，原来的来源也留着；助手认为它不再支持改后的内容时，会重新标注这个条目的来源把它去掉。你自己在页面上改条目时，你没动的那几项来源照样留着、位置跟着内容走；你改写了的那句话（一个字段，或列表里的一项），原来的来源去掉，不加新的来源：条目上的话都算你自己的，谁改的、怎样改的看修订。条目一条来源都没有时，底部「来源」一节不显示。

条目右上角的下拉框列出它改动过的修订；选一个，就看到它在那次修订时的样子，画线的地方是和它上一次改动的差别。修订列表偶尔没读到时，下拉框里写「修订列表没读到，再打开一次试试」，回到列表再打开这个条目即可。

**上次确认以来智能体改了哪里。** 自你上次确认的那次修订以来（从没确认过的，自它新增的那次修订以来）智能体改过的字段，整块加琥珀色左边线，顶部说明写「与你上次确认的修订 K 相比，改了这几处」：划掉的是修订 K 的写法，加底线的是现在的写法。几次修订的改动累计标出。你自己改的字段不加框。打开详情就记为已读，所以框在你打开的那一刻定下来：详情开着时一直在，下次再打开就不再出现。这些框与「刚改」只是提示你智能体改过哪里，不影响已读，也不挡完成任务。智能体最近一次工作改过的条目，在列表里标「修订 N · 刚改」。

条目下方的按钮可以直接操作：**修改**（Edit）打开字段编辑，**保存**（Save）存成一次新的修订；**删除**（Delete）删掉这个条目；**先不管，保留**（Keep pending）把问题条目的状态改为用户决定保留。条目右下角只显示状态，已读不能撤回。问题条目写下之后不能直接修改，详情底部只有**先不管，保留**和**删除**：要回答它，就在对话里告诉智能体，它会改牵涉的条目，再问你这个问题是否已解决。保存你自己的修改、或把问题条目标为先不管，也同时算作确认了这个条目。在列表里勾选几个条目，点**把选中的这几条标为已读**（Mark these as read），可以一起标为已读。**‹ 回到列表**（Back to list）回到条目列表。每次改动都是一次新的修订，不会覆盖旧内容。

**问题跟着条目走。** 问题条目的「关联条目」把它挂到牵涉的条目上。列表里，有未解决问题牵涉的条目在状态徽标旁再带一枚琥珀色的**问题 N**，N 只数未解决的问题，为 0 时不显示；问题是这个条目唯一缺的东西时，它那一枚徽标直接写「问题 N 未解决」。问题条目自己只写它的状态：未解决（琥珀）、已解决（绿）、用户决定保留（绿边框）。条目详情的标题行之下是**挂在这条上的问题**一区，每个未解决的问题一张卡片，写着编号、种类、状态、事项和助手建议的处理；没有未解决的问题牵涉这个条目时，这一区不显示。卡片上可以直接写回答再点**回答**（Answer）：对话区会发出「回答 TBD-002：你写的话」，智能体据此修改牵涉的条目；输入框空着时点**回答**只往对话区输入框里预填开头，不发送。**先不管，保留**与别处相同。已解决和用户决定保留的问题不显示在条目上；在卡片上点了先不管，保存之后那张卡片随即不再显示。这些问题仍在「问题」页签里，怎样了结的在修订页签里看得到。**回答**在输入框空着时只预填文字、不发送，所以只在任务已结束或助手不可用时变灰，助手工作时、有未保存的条目编辑时照常可点；输入框里写了字、点它就要直接发出去时，它与对话区的发送键一样，助手工作中或有未保存的条目编辑时也变灰。**先不管，保留**是真正的写入，与其它写入按钮一样，在任务已结束、助手不可用、助手工作中、正在保存上一次修改时变灰；有未保存的条目编辑时它不变灰。「问题」页签的问题卡片上，**回答这个问题**只预填，灰化规则与输入框空着时的**回答**相同。鼠标停在灰掉的按钮上会说明原因。在「问题」页签里点问题卡片上牵涉的条目编号，会打开那个条目，顶部多一行**‹ 回到问题列表**（Back to the question list）。那个问题未解决时，它的卡片排在第一张并高亮，其余问题折叠成一行「还有 N 个问题 ▸」，点开展开；那个问题已经解决或已经先不管时，顶部那一行照旧，它的卡片不显示，其余未解决的问题照常列出。没有关联条目的问题只留在「问题」页签里。

同一个条目在两个浏览器页签里都打开了编辑，一边先保存，另一边再保存就会被拒绝：页面右上角出现一条红色提示，写明它已经被改到修订 N，一直停着，点 × 才关。不做合并；点提示末尾的**打开最新**退出编辑、看到现在的内容，再改一次。

**右上角的提示。** 刚发生的事统一在页面右上角报一条，新的在最上面，最多同时三条：成功（绿，4 秒后淡出）、进行中（蓝，带进度条，做完后换成结果）、警告（琥珀，8 秒后淡出，情况还在时重新出现，例如与服务器的连接断了）、失败（红，一直停着，点 × 才关）。鼠标停在一条上时它暂停计时。有的提示末尾带一个动作，例如「打开最新」「看评审页签」。你发出的话没有发出去时，除了一条失败提示，那句话也留在对话区原处、写明没有发出去；发出这句话的输入框这时如果还空着，原文会放回去，可以直接重发；你已经接着打了新字时，保留你的新字。

**连接断了、服务停了。** 页面与服务的连接断了时，右上角的警告写明「连上之前，你的修改发不出去」，页面自己重连，连上之后补上断开期间的变化。连续约一分钟还连不上，警告换成一条一直停着的红色提示「连不上服务，可能已经停止。你可以稍后刷新这个页面再试。」，页面改为每 30 秒试一次，连上之后它自己收起。页面与服务之间隔着一层转发（例如反向代理）时，服务停了或正在重启，打开或刷新页面、以及页面上的操作会提示「连不上任务服务，可能正在重启。请稍后再试；一直不行，请告诉管理员。」。服务正常退出时，打开着的工作视图会整页换成「服务已退出，可以关闭此窗口」（桌面包）或「服务已停止。恢复之后刷新这个页面即可继续。」（服务器），不再重连。

**助手退出了。** 助手因故退出、服务还在运行时，对话区输入框上方有一条蓝色提示「助手已经退出，下一次说话时会重新启动。」页面照常可用：你说一句话、点卡片按钮或者修改条目，服务都会先把助手启动起来、接回这条会话，这几秒里提示换成「助手正在启动」，发送按钮暂时不能点。服务重启之后没能接上这条会话时，提示写「助手没有接上这条会话，下一次说话时会重新启动。」，同样不拦住操作。只有助手启动不起来（例如没有配置模型）时整页才变成只读，并写明原因。

智能体改了你看过的条目，这个条目仍是已读，列表里标「修订 N · 刚改」，打开详情能看到改过的字段；要不要再看由你决定。条目列表上方的「还有 N 条未读 · 筛出来看」和筛选里的**未读**（Unread），列出你从没打开过的条目。

**修订页签**（Revisions）列出任务的每一次修订，最新的在上面。每张卡片写「修订 N · 时刻 · 助手」或「· 你在界面上改的」、触发它的事（助手记下了它对你那句话的理解、这次修订对得上其中一项时写「因为你说：纠正：UC-003 的参与者改为借还台管理员」这样的一句；否则写回应你的哪句话、点了哪张卡片、哪次直接操作），以及它碰到的每个条目：新增、修改、删除或恢复，改了哪些字段，行尾是**查看差异**（Show changes）。点卡片，条目区高亮它碰到的条目，集合页签上标出个数，筛选行的「修订 N 碰到的条目 ✕」可以取消。**撤销这次修订**（Undo this revision）产生一次新修订，把那次修订碰到的每个条目改回原样（删掉的恢复，新增的删除）。那次修订碰到的条目之后又改过（或已经删掉）时撤销不了，按钮预先变灰，鼠标停在上面会说明「这次修订碰到的条目之后又改过，不能撤销；要改请直接改条目」。**按此修订生成文档**（Generate a document from this revision）打开那次修订的生成文档对话框。智能体工作期间这个页签照常能看，只是撤销变灰。

**评审。** 功能用例、非功能需求与约束三个集合里的条目，要评审通过才能完成任务。评审由你发起：条目区顶上的**评审 N 条待评审的条目**（Review N items waiting for review）评全部在当前所在的修订上还没有评审记录的条目，条目详情里的**评审这条**（Review this item）只评这一条，完成条件里的**评审这 N 条**（Review these N）评那里列出的条目。助手工作期间这几个按钮变灰。评审在后台进行，每条约十秒，一次并行四条，你可以接着做别的：页面右上角一条蓝色提示显示「评审中 3/12」和正在评的条目，评完换成结果，末尾带「看评审页签」。助手的程序在评审中途退出时，这条提示收起，评审的按钮恢复可用，可以再评一次。评审者按编了号的规则（例如 UC-R7）逐条核对。违反必选规则的发现是**问题**（红色），有一处条目就评审不通过；违反可选规则的是**建议**（琥珀色），不影响通过。评审通过的条目，详情里标题下面有一块绿色的说明，例如「评审通过：按 14 条规则逐条核对，没有发现问题。」，第二行写评审的时刻与修订；点「看这 14 条规则」列出这次核对的规则（编号与条文），这个任务里关掉的规则不在其中，末尾写另有几条已经关闭。评审页签里通过的条目后面有「核对了哪些规则」，点开是同一句说明与同一份规则。评审之后又改过规则时列不出当时核对的规则，这一行改写「评审之后规则改过，这里列不出当时核对的规则。」发现标在对应的字段旁；点「违反」后面的规则编号可以看规则原文，点**让助手照这条改**（Let the assistant fix this）会往输入框里填好一句请助手修改的话。同一个条目在同一次修订上、按同一套规则只评审一次：条目改出新修订、或者规则改了之后，才要重新评审。在那之前**评审这条**是灰的；评审不通过的条目，鼠标停在这个按钮上会提示接下来能做什么：照发现修改之后再评，或者保留这种写法。右侧栏的**评审**页签（Review）先回答现在有什么要你处理。顶上一行写现状：「3 个条目还没有评审。」，右边是唯一的按钮**评审这 3 个条目**（Review these 3 items）；规则改过之后写「规则改过，3 个条目要重新评审。」；在页面上发起的评审进行时写「正在评审，已经评完 2 个，共 5 个。」，下面一条细的进度线（助手在对话里发起的评审，这里不显示进度）；有问题时写「有 4 处问题等你处理。」；全部通过时前面一个绿色的小对勾，写「全部条目都已经通过评审。」。下面的**要处理的**（To handle）按条目分组，每个条目一张卡片，写编号与标题；每一处问题写位置（例如「基本流程 第 2 项」）、问题的说明、「改法：」，后面是**让助手照这条改**（Let the assistant fix this）、**保留这种写法**（Keep this wording）与「依据的规则」，点「依据的规则」在原地展开规则的编号与条文。评审进行时，评完一个条目，它的问题就出现，排在已有的后面。条目多于三个时只摊开前三个，其余每个条目折成一行，写有几处问题，点了在原地摊开。**建议**（后面写「不影响通过」）、**已经没事的**（评审通过的条目与你保留了写法的条目）、**评审记录**（每次评审一行，最新的在上，例如「评审了 5 个条目：4 个通过，1 个有问题。」，助手发起的末尾写「由助手发起」）默认收起，点标题展开。已经改掉的问题、按改之前的规则评出的问题、条目后来又改过的问题都不显示：评审之后条目改过或者规则改过，这个条目算还没有评审。页签角标是要处理的问题的处数，与顶上一行的数相同。点**保留这种写法**，在原地写理由（也可以不写），点「保留」或按回车保留，点「取消」或按 Esc 收起。保留是对整个条目的：条目有几处问题时，输入框上面写着它们都按你的决定算通过。保留之后，这条按你的决定算通过；条目再改动，评审要重做。它挪到「已经没事的」里，写着它的问题与你的理由，「撤销保留」也在那里。条目详情里每条问题的第二行写着它的去向与你写的理由，行末有「保留这种写法」：点它之后可以写理由（也可以不写），再点「保留现在的写法」；「撤销保留」也在这一行。保留之后，标题旁的徽标写「评审不通过 N 处 · 已保留」。页签最下面一行「评审规则（共 34 条，开着 32 条）」，点了从右侧滑出规则的面板，按集合分组，每条只有开关、编号与条文；点「关闭」、点面板左边那一窄条或者按 Esc 收回。规则的状态由开关表示：绿色、带一把白色的锁的是必选规则，不能关；绿色、不带锁的开着，可以为这个任务关掉；灰色的已经关闭。页面上不能把规则升为必选。这个任务里以前升为必选的规则照开着的显示，鼠标停在它的开关上会提示「这条规则已经升为必选，违反它算问题。」；它可以直接关掉，关掉时升为必选一并撤销，再打开时它是可选规则；改了规则，这个集合的条目都回到待评审，已有评审记录不变。评审结束时，对话区只显示一行「评审完成：X 条合规、Y 条不合规……」和「看评审页签 ›」。筛选里的「待评审」「评审不通过」「已保留写法」「评审通过」分别列出这几种条目：「评审不通过」只列你没有保留写法的，保留了写法的列在「已保留写法」里，「评审通过」只列真正评审通过的。助手不会自己去评审；你在对话里要它评审，它才会评，并把结果转告你。

## 4 完成任务并生成文档

条目列表上方那行汇总（例如「12 个条目 · 待评审 4 · 评审不通过 1 · 已保留写法 2 · 3 条未读；问题 3 条未解决 ▾」；「评审不通过」不含你保留了写法的条目，保留了的另写「已保留写法 N」，为 0 时不写；每个数与同名的筛选列出的条数相同）点开后就是完成条件（completion conditions），任务页上也列着同样的完成条件。对随附的这个任务类型来说，每个集合都要满足自己的条件（例如每个用例都评审通过、没有从没看过的用例，且没有遗留未解决的问题条目）。评审那一条把还没评审的、评审不通过的、评审不通过但你保留了的（这条按你的决定算通过）三类条目分开列出，旁边有「评审这 N 条」与「打开 X」两个按钮。智能体会先告诉你还有哪些从没看过。任务完成之后只读、不能重新打开，所以完成要你亲手点一下；在对话里打字说「完成吧」不算。智能体一轮工作结束时全部条件都满足，它用「请选择」卡片问你这个任务是否已经完成，问句写明事实与后果，例如「功能用例一共 3 个条目，都已经评审通过或者由你保留了写法，你也都看过了，没有未解决的问题。这个任务是否已经完成？提交之后交付物不能再改，仍然可以生成文档。」，两个选项是**已完成，提交交付物**与**还没完成，继续修改**。你在最近一张这样的卡片上点了**已完成，提交交付物**，而且点了之后交付物没有新的修订，智能体才能把任务标为已完成；否则它要重新问。已读、评审、保留写法不产生修订，不会让它重新问。条件是在智能体没有工作时、因为你在页面上的操作才满足的（例如最后一条评审通过，或者你打开了最后一条未读的条目），工作视图条目区顶部会出现一条绿色提示条，写「完成条件都满足了。」和一句同样写明事实与后果的问句。这句问句由页面按条目算出，写法与卡片上的略有不同：要求你看过、但不评审的集合（例如领域说明）单独点名并写个数，例如「2 条领域说明你也都看过了」；有问题条目时写「2 个问题都已经解决或者由你决定保留」，一个问题条目都没有时不写这一句。提示条上只有一个按钮**已完成，提交交付物**。点了先弹出确认框「提交之后这个任务变成只读，交付物不能再改，仍然可以生成文档。确定提交吗？」，按钮是**提交**与**取消**；点**提交**之后任务标为已完成，不经过智能体，对话区多一句「界面操作（不是用户打的字）：用户在页面上确认这个任务已经完成，提交了交付物（修订 N）。任务已标为已完成，交付物不能再改，仍然可以生成文档。」智能体工作期间，或者这条会话里有一张智能体问任务是否已经完成、你还没回应的卡片时，提示条不显示；你在那张卡片上点了**还没完成，继续修改**之后，提示条重新出现。确认框开着时交付物又有了新的修订，这次不提交，提示条上写「这次没有提交：你看到的是修订 N，交付物现在已经是修订 M。请看过现在的内容再提交。」。提示条只在工作视图里有，任务页上没有。完成之后任务变为只读，仍然可以生成文档。

点条目区顶上、文档页签里、任务页上的**生成文档**（Generate document），或修订页签里某张卡片上的**按此修订生成文档**。在对话框里选一个修订（缺省是最新的），再勾选要包含的条目，列表里是那次修订时交付物里的条目；整份文档按那次修订生成，右侧的预览随之变化，点**下载 Markdown**（Download Markdown）保存文件。文档开头写明按哪次修订生成，每个条目标着它的内容来自哪次修订、在那次修订上有没有确认与评审（确认写明依据：已读、用户修改，或早期版本的明确确认）；未确认、未评审的条目照样包含进去并如实标出，问题条目只写种类和状态。文档按任务目录里的模板渲染，不经过模型改写。文档随时都可以生成，任务完成之后也可以。按最新修订与按早先修订各生成一份的例子见[教程](tutorials/srs-authoring.zh-CN.md#第六幕拿走文档回头看它做了什么)。

## 5 跑一遍示例

`examples/library-lending/` 里有一段虚构的学校图书馆需求说明（[`requirements.md`](../examples/library-lending/requirements.md)），以及一个只用 HTTP 接口走完整个流程的脚本。任务服务启动之后（见[部署](deployment.zh-CN.md)）运行：

```bash
examples/library-lending/run.sh http://127.0.0.1:8790
```

脚本会建任务、上传这段说明、开会话、请智能体开始工作、等它回复，最后把生成的文档写到当前目录下的 `srs-<任务编号>.md`。脚本只需要 `curl` 与 `python3`，不必激活虚拟环境。它每 5 秒打印一次智能体的进度；用默认模型跑一遍通常要 1 到 3 分钟，产出 10 到 20 个条目。这段说明有意留了几处没说清，好让智能体有事可问。

脚本建的任务也会出现在网页界面的任务列表里，可以在那里打开它接着做。

## 6 两种操作方式

| 方式 | 命令 |
|---|---|
| 网页（后端加浏览器界面） | `scripts/dev.sh`，然后打开 `http://localhost:5680` |
| pi 自带的终端界面 | 先在网页里（或经接口）建任务，再 `scripts/tui.sh tasks/<任务编号>` |

`scripts/tui.sh` 用任务服务同一份启动配置起 pi 自带的终端界面，所以助手手上的工具、提示、skill 与模型都相同；打字即可对话，输入 `/tw-board` 查看交付物。它可以带 `--profile <名字>`、`--label <名字>`（会话文件放在 `$TASKWRIGHT_RUNS_DIR/pi-sessions/<名字>/`，缺省 `tui`）、`--continue`（续接这个名字下最近的一条会话）与 `--session <会话文件>`。pi 退出后，它把这次写过的会话文件打印出来。通过 HTTP 接口脚本化使用的方法见[接口参考](api.zh-CN.md)。

## 7 用观测台查看智能体做了什么

观测台是只读的本地网页应用，不改任何数据。它读任务数据库，以及后端在每次启动 pi 时写下的归档。

```bash
python3 -m taskwright_observatory --runs ./runs --workspaces ./tasks
# 然后打开 http://127.0.0.1:8770（--port 可改端口；按 Ctrl+C 停止）
```

- `--runs`：推荐传任务服务的 `--runs` 目录（上面的 `./runs`）。任务服务在这个目录下为每个任务建一个归档目录（直接包含 `pi-events/` 与 `pi-sessions/` 两个子目录的那一层），观测台把其中每一个都收进来；每次读取都重新查找，所以观测台启动之后新建的任务也会出现，不用重启。只想看一个任务时，传那个任务的归档目录 `./runs/<任务编号>`。`--runs` 可以写多次，同时看几个目录。

- 在 pi 自带终端界面（`scripts/tui.sh`）里跑的会话不产生事件归档，观测台里看不到。
- `--workspaces`：放任务目录的上级目录，也就是任务服务的 `--tasks`。不给时，`--runs` 传的是 `./runs` 这一层而它旁边有 `tasks/` 目录的，取那个 `tasks/`；传的是一个任务的归档目录的，取它的上一级。
- 观测台启动时不打印任何内容；命令跑起来之后直接打开上面的地址。
- 文件有变化时会重新读取：跑完新会话、或者新建了任务，刷新浏览器即可。

| 页面 | 看什么 |
|---|---|
| 会话列表 | 一行一条会话：起止时间、运行次数、轮数、模型请求次数、工具调用次数、被拒次数、结局；每行有「进入会话详情」与「进入任务页」两个链接 |
| 任务 → 任务页 | 任务的过程按阶段排列；点开一个阶段看这段时间的对话和对交付物的每次改动，再点开一轮看每次工具调用的参数、返回与耗时。右侧交付物看板列出每个条目当前所在的修订、来源、评审与确认状态（评审状态看这个修订上最后一次评审：合规是「评审通过」；不合规、但之后你保留了写法是「已保留写法」，格子按通过显示；否则是「评审过，没有通过」。观测台不看规则指纹，改过评审规则之后，旧规则下的评审照样显示），以及完成条件还差哪几项；点一个条目，看它在改动过的每次修订下的样子。页头有一行「对话」，写三件事：还在等你回应的助手行为、助手连着两次及以上运行问了都没得到回应的条目、按你的意思改过两次及以上的字段。每次运行那一行标出它在会话里的运行号（运行号 rN，与按任务数的序号不是同一个数），这一轮结束时助手仍没有为你这句话写下合格的理解的，另标「这一轮没有合格的理解」，一轮只标一次；点开一次运行，用户那句话下面是这次运行的对话行为，助手文字里没有匹配上任何一种格式、或解析不了的 JSON 片段以灰色列出（只是诊断，不算失败），展开看每个片段的前 200 字与校验错误或解析错误；对话行为的内容是：左列是你的行为（功能如「纠正（correct）」、针对的条目与字段、回应了助手哪一项、助手的把握、摘要），右列是助手的行为，各标「已回应（rN-M）」「等回应」或「不等回应」。 |
| 会话详情 | 与任务页相同的视图，只看一条会话 |
| 系统健康 | 核对这套系统本身：配置的工具是否真的加载了、库里的数据与事件是否对得上、被拒的调用后来有没有改正 |
| 概念对照 | 页面上每个词的含义 |

被拒的工具调用会标在它发生的位置，点开那一轮就能看到工具返回的原因。配了 Langfuse 时，每次运行和工具调用还带着到 Langfuse 的链接。

在终端里快速查看：`python3 -m taskwright_observatory.dbshow tasks/<任务编号>` 打印任务、每个条目改动过的修订与来源、修订和最近的事件；`python3 -m taskwright_observatory.check_db tasks/<任务编号>` 核对库里的数据与事件是否一致。

## 8 在设置里测试语言模型

**先按用途添加模型服务。** 模型服务按用途分两类：提供语言模型的，助手靠它工作；提供嵌入模型的，知识库按意思查找时用它。在设置页面「模型」一栏点**添加模型服务**：第一步选它提供哪一类模型，第二步选种类，第三步填接口地址与密钥。一个模型服务只提供一类模型；同一个地址两类模型都有时（例如一台 ollama 上既有语言模型又有嵌入模型），添加两次，地址相同、用途不同。清单按用途分成「语言模型」「嵌入模型」两组，用途也写在每个模型服务的详情里；更换语言模型时只列出语言模型那一组里勾上的模型，更换嵌入模型时只列出嵌入模型那一组的。分辨不出模型是哪一类的模型服务，取回的清单里是它的全部模型，请只勾这一类的。从更早的版本升级上来、原来一个模型服务里两类模型都有的，任务服务启动时会把它拆成两个：嵌入模型移到名称后面带「（嵌入模型）」的那一个上，原来选定的模型照旧，不用重新选。

**升级到这一版之后要做两件事。** 一、到设置里选定语言模型。桌面包不再带默认的模型；没有选定时页面顶部提示「还没有选定语言模型，助手现在不能工作。」，点「去配置模型」进设置页面，添加模型服务并选定。二、用 ChatGPT 订阅的，用新的入口重新登录一次：在运行任务服务的电脑上打开命令行，运行 `pi`，输入 `/login`，在列表里选 OpenAI，按提示用 ChatGPT 订阅登录。以前在旧的入口登录过的不算数，Codex 订阅的详情里会写「这一版改用新的登录入口，请重新登录一次」。登录之后回到设置页面点「重新检查」，再点「获取模型列表」。助手平时不访问外网，可选模型的目录不会自己变新；要更新时在 Codex 订阅的详情里点「更新模型目录」，只有这一次会访问外网。

配置填好了，不等于模型真的能用：密钥填错、型号写错、模型服务起了却没有载入模型、订阅过期，都要等到在任务里跟助手说话才看得出来。设置页面「模型」一栏里，「助手用的语言模型」那一行右边有**测试**按钮，可以先试一次。

点**测试**，确认框里写明要用哪个模型。点**开始测试**之后，服务照任务里的办法起一次助手，让模型读一个小文件并回答一个问题，然后把助手停掉。文件里写着一批货有多少箱，箱数每次随机取；问模型的是「这批货一共有多少箱？」，模型要真的读了文件才答得出来。**这会向模型服务发一次真实的请求，商业接口可能产生很少的费用。** 测的是助手现在实际会用的语言模型：选定了就是选定的那个，没有选定时是这一行写着「现在用的是」的那一个。测试最多等 90 秒，其间不能更换语言模型。

结果写在这一行下面：「这一次测试通过，用时 N 秒。」，或者「这一次测试没有通过：」后面跟原因；两种情形下面都另有两行，「问模型：……」是问模型的那句话，「模型回答：……」是模型答的话，模型没有回答时写「模型没有回答」。没有通过的原因例如模型没有调用读文件的工具、模型的回答里没有文件里写的箱数、模型服务报错、90 秒内没有做完、模型服务还没有设置密钥或者还没有登录。结果只说明这一次：换了语言模型或者刷新页面，结果就清掉。

**嵌入模型也可以测试。**「查找用的嵌入模型」那一行右边同样有**测试**按钮，选定了嵌入模型才能点。确认框里写明要用哪个模型；点**开始测试**之后，服务把一句话「这批货一共有 N 箱。」（箱数每次随机取）送去换算成一串数字，这一种测试不起助手。**这同样会向模型服务发一次真实的请求，商业接口可能产生很少的费用。** 测试最多等 60 秒。两种模型同一时间只能测一种：有一种在测的时候，两行的「测试」与「更换」都不能点。

通过时结果有三行：「这一次测试通过，用时 N 秒。」；「送去换算的话：……」是实际送去的全文；「算出来的数字串长度：……」是模型给的那串数字有多少个数，由模型定，例如 1024 或 4096。没有通过时只有一行，「这一次测试没有通过：」后面跟原因，例如还没有选嵌入模型、连不上这个模型服务、模型服务拒绝了这个密钥、模型服务里找不到这个模型或者它没有嵌入模型的接口、模型服务回答了错误。更换了嵌入模型（只改查询前缀也算）或者刷新页面，结果就清掉。

「送去换算的话」前面带着你更换嵌入模型时在「高级」里填的**查询前缀**，可以借这一行核对前缀填得对不对。前缀与查询是直接接在一起的，中间不会替你加空格、换行或冒号，所以前缀要自己写到结尾。例如 Qwen3-Embedding 这一类要在查询前面加一句任务说明的模型，前缀写两行：第一行 `Instruct: Given a web search query, retrieve relevant passages that answer the query`，第二行只写 `Query:`，冒号后面不换行。测试通过后，这两行后面紧跟着「这批货一共有 N 箱。」。不需要任务说明的模型把前缀留空。

## 9 知识库文档的换算

知识库按意思查找之前，要先用嵌入模型把每份文档换算成数字串。这一版只做换算并显示进度，按意思查找还没有接进助手，助手照旧按字面查找。

**在哪里看。** 知识库页面的文档表格有「换算」一列，每份文档写着**未换算**、**等待换算**、**换算中**（括号里是算完了几个片段、一共几个）、**已换算**或者**换算失败**；没有文字的文档写「没有文字，不用换算」。表格上面一行是这个知识库「已换算 N / M」（按文档份数）、进度条与用的嵌入模型。有文档在等待换算或者换算中时，页面每两秒自己更新一次，不用刷新。还没有选嵌入模型时，这一行写「还没有选嵌入模型，这些文档没有换算，只能按字面查找。」，点**去设置里选**。

**什么时候换算。** 选了嵌入模型之后上传的文档会自动换算。别的情形要你点一下：选了嵌入模型、而且这个知识库里有没换算好的文档时，表格上面那一行有**开始换算**按钮。任务服务重启之后不会自己接着算，正在算的与排着队的都回到「未换算」，再点一次**开始换算**即可。文档一份一份地算。换算要向模型服务发请求，文档多时要一些时间，**商业接口会按量产生费用**。

**没有算成。** 只关一份文档的原因（例如文档里有一段文字超过了这个模型一次能收的长度）：这份文档写**换算失败**，下面一行是模型服务给的原因，旁边有**重试**；别的文档照常换算。与文档无关的原因（连不上模型服务、到时间没有回答、密钥被拒绝）：整个换算停下，表格上面那一行写「换算停下了：」加原因，文档仍是「未换算」；排除之后点**开始换算**。

**更换嵌入模型。** 不同的嵌入模型算出来的数字串互相比不了，所以换了嵌入模型，全部文档都要重新换算。知识库里已经有文档时，在设置里选了另一个嵌入模型再点**用这个模型**，会先问一句「换了嵌入模型后，知识库里的 N 份文档要重新换算，换算完成前按意思查找暂时不可用。商业接口可能产生费用。」；点**更换并重新换算**之后选择保存，后台随即开始换算，进度在知识库页面上看。第一次选定嵌入模型时同样先问一句。只改查询前缀不用重新换算。改成「不用嵌入模型」不问，已经换算好的数字串留着，再选回同一个模型时不用重算。
