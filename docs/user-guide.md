# User guide

This guide is for using Taskwright once it is running (see [deployment.md](deployment.md) for installation and model setup). It walks through one task in the web interface, from creating it to generating the document, then covers the example script, the other ways to work, and the observatory. It uses the bundled task type, *software requirements specification*, and the example material in `examples/library-lending/`. If you would rather follow one task step by step with screenshots first, start with the [tutorial](tutorials/srs-authoring.md).

Start the backend and the web interface with `scripts/dev.sh` (see [deployment.md](deployment.md)) and open `http://localhost:5680`.

**Supported browsers.** Chrome 125, Edge 125 (the same engine as Chrome), Firefox 128 and Safari 18, and anything newer. In a browser that is too old the page shows no interface, only the line 这个浏览器版本太旧，请更新到两年内的版本（Chrome 或 Edge 125、Firefox 128、Safari 18 以上）。 ("this browser is too old; please update to a version from the last two years (Chrome or Edge 125, Firefox 128, Safari 18 or later)"). A browser slightly older than these may still open the page but is not supported; when it cannot draw a PDF material, the file is shown in the browser's own viewer instead (see "Reading a PDF in the Materials tab" in section 2).

**The data upgrade after a new version is installed.** When a new version starts for the first time and this computer holds tasks created by an earlier version, the page first shows 数据升级 ("data upgrade") in place of everything else. It says how many tasks are to be upgraded, in which directory the backup made before the upgrade goes, and that it usually takes less than a minute. Click **开始升级** ("start the upgrade"); the page shows how far it has got. When every task succeeded, the page goes on to the usual interface by itself, and the tasks hold what they held before. When a task failed, the page stays, says how many succeeded and how many did not, and shows a report (the result for every task and where the backup is); **继续使用** ("go on") leads to the usual interface, where the failed tasks are marked 需要处理 ("needs attention") in the task list with the reason and cannot be opened for now, while the others work as usual. When the whole upgrade failed (the backup did not fit, for example), the data is as it was, the page says why, and **再试一次** ("try again") starts it once the cause is gone. The backup is not removed automatically. Two more kinds of tasks in the list cannot be opened: 需要升级 ("needs upgrading") is an earlier task that was put there while the program was running and is upgraded after a restart; 需要更新的程序 ("needs a newer program") was written by a newer version and has to be opened with that version or a newer one. On a server shared by several people the administrator upgrades with a command on the server; see section 8.1 of the [deployment guide](deployment.md).

## 1 Create a task

The interface is in Chinese; button names in this guide are given in English with the original label in parentheses. The page title is 需求工作台 (requirements workbench).

On the task list, choose **New task** (新建任务), pick the task type, give it a name (and optionally a domain tag), and choose **Create** (新建). The dialog does not take files; the new task's page opens instead.

The task page is the overview of one task and the way into its work. It has six parts, from top to bottom.

- **Breadcrumb and header**: the task's name, its status (green for 进行中, in progress; grey for completed and abandoned), the task type, the buttons **Generate document** (生成文档) and **New session** (新建会话) on the right, and below them a line with the creation time and the last activity.
- **Completion conditions** (完成条件): a score on the left, for example 完成条件 1/3, where the second number counts only the conditions that apply now and the first those of them that are met. On the right every condition is one line: a green tick when it is met; an amber ring when something is missing, with the items named, for example 功能用例的每个条目都要评审通过，UC-001 和 UC-002 还在等评审。 ("every use case must pass review; UC-001 and UC-002 are waiting for review"). The conditions of collections that have no items yet are not listed one by one: they are gathered into one grey line at the end, for example 非功能需求、约束现在还没有条目，它们的完成条件暂时不用核对。 ("the non-functional requirements and the constraints have no items yet; their completion conditions need not be checked for now"), and they do not count in the score. When everything is met the whole part becomes one sentence, 完成条件已全部满足，可以在会话里请助手标记完成。 ("all completion conditions are met; ask the assistant in a session to mark the task complete").
- **Deliverable** (交付物): one card per collection with its name (the overall analysis collection is shown as 业务说明, as on its tab in the work view) and id prefix, the number of items and a line 评审通过 N/M · 已读 N/M ("passed review N of M · read N of M"). N counts only the items that really passed; when you kept the wording of items that failed, the line goes on with · 已保留写法 K ("wording kept K"); a collection that is not reviewed shows only 已读. Hover over a card for the details. A collection without items has a grey card that says 还没有条目。 ("no items yet"). 最后改在修订 N ("last changed in revision N") is at the right of the heading. Click a card to enter the work view of the most recently active session with the items area on that collection's tab; while the task has no session the cards cannot be clicked. Each collection has its own colour, which goes with the collection's name; the colour only tells collections apart and says nothing about status.
- **Sessions** (会话): one line per session with its first sentence, the time of its last activity and how many revisions it produced, most recently active first; a small green dot marks the session the assistant is attached to. Click a line, or **打开** ("open") at its right, to enter that session.
- **Materials** (材料) and **Knowledge bases in use** (选用的知识库): two cards side by side, one above the other in a narrow window.

The last activity in the header and the session list are updated when the assistant finishes a turn, without reloading the page.

The materials card lists each material's name, size and upload time, with **View** (查看) on every line. An upload here is always a material: drag files onto the dashed box or click it to choose them; reference documents are not uploaded here but on the knowledge base page. A material that has not entered the conversation also has **Replace** (替换) and **Delete** (删除). **Replace** lets you choose a file and then asks for confirmation with 用新文件替换这份材料，旧文件就没有了；助手下次开始会话时看到的是新文件。 ("the new file replaces this material and the old file is gone; the assistant sees the new file when it next starts a session"); after you confirm, the material is the new file. The new file may have another name and another type, and the rules for type and size are those of an upload. As for **Delete**: as long as no session of the task has been active since the upload, the material can be deleted, after a confirmation that says 删除之后这份材料就没有了，助手下次开始会话时不会再看到它。 ("after deletion the material is gone and the assistant will not see it when it next starts a session"). Once anything has been said in a session after the upload, the material has entered the conversation: **Delete** is no longer shown, and **Replace** turns grey and cannot be clicked, with the reason shown when the pointer rests on it. To change the content from then on, upload a new file and tell the assistant in the conversation to go by the new one. The knowledge base card lists the knowledge bases the task uses with their number of documents: the general knowledge base is used by every task and cannot be removed, the others have **不再选用** ("stop using"), and **选用别的知识库** ("use other knowledge bases") opens a list to tick; the assistant looks only in the knowledge bases in use.

Plain-text `.md` or `.txt` files, Word `.docx` files and PDF files up to 5 MB each are accepted; a larger file is refused before it is sent, with the message 单个文件不能超过 5 MB。 ("a single file cannot exceed 5 MB"), and so is a file of another type, with 只接受 .md、.txt、Word 的 .docx 与 PDF 文件。 ("only .md, .txt, Word .docx and PDF files are accepted"). A task never holds two materials with the same content or the same name. A file whose content is exactly that of a material already in the task, whatever its name, is refused with 这份文件与已有的材料《…》内容完全相同，没有重复保存。 ("this file has the same content as the material … ; it was not saved again"). A file with the name of a material that has other content is refused with 这个任务里已经有一份叫《…》的材料，内容与这份不同。请给文件换一个名字再上传。 ("this task already has a material called … with other content; rename the file and upload it again"); rename it and upload it again. In both cases nothing is saved and the material list stays as it was. Names are compared without regard to case or to white space at either end; names that differ only in full-width and half-width characters (for example full-width and half-width brackets) are different. **Attach a material** (附一份材料) in the work view's conversation follows the same rules. For a Word file the service also generates a text version for the assistant, in Markdown, which keeps the headings, numbering, lists and tables and links the pictures; the list does not show the text version, and **View** on a Word file shows the file page by page in its original layout. If the layout of a Word file cannot be drawn, **View** and the Materials tab show 这份 Word 文件在这里显示不出来，但文件已经上传好了：助手仍然能读到它的内容，条目的来源仍然有效，不需要重新上传。 ("this Word file cannot be shown here, but it has been uploaded: the assistant can still read it, the items' sources are still valid, and there is no need to upload it again"); the assistant reads the text version and is not affected, and the source labels of that file give only the file name and the section, without the page and the position on the page. The assistant sees a newly uploaded material from the next session it starts, so upload before you open a session.

**PDF materials.** A PDF is parsed when it is uploaded, to take the text out of it, so the upload takes a little longer than for other files: usually under a second, a few seconds for many pages. The assistant can read it once that is done. These PDFs are not accepted, and the upload says why: one without any readable text (most likely a scan; the message is 这份 PDF 没有可读的文字（可能是扫描件），本版不支持。, and this version does no text recognition); one that needs a password to open; one over 1000 pages or 3 million characters; and one whose parsing is not finished after 60 seconds (the message says how long it took and which page it reached). A PDF in which only some pages have no text is accepted; the assistant knows which pages could not be read, and what they say is for you to tell it. Tables in a PDF are read row by row, not cell by cell. When the assistant cites a PDF material, the source points at a block of a page, and the excerpt of one source never crosses a page. Documents in the knowledge base can be PDF files too, under the same rules, up to 20 MB each.

A task can have several sessions (conversations); all of them work on the same deliverable. Choose **New session** (新建会话) to open one; the work view opens. The assistant starts in the background, and a status message at the top of the conversation tells it what the task looks like and which materials and knowledge bases it has. The message is written for the assistant, so the conversation shows it folded into one line, for example 助手开始这条会话时看到的任务状况：2 份材料 · 2 个知识库 6 份文档 · 完成条件 1/3 · 问题 0 条未解决 ▸ ("the task as the assistant saw it when it started this session: 2 materials, 2 knowledge bases with 6 documents, completion conditions 1/3, 0 open issues"). Click the line to unfold the full text under the heading 系统说明 ("system note"), and click again to fold it; when you open the session again it is folded. The full text opens with 这条会话开始时（time）的任务状况： ("the task at the start of this session"). When an earlier session is resumed and something changed since, the folded line reads 助手续接这条会话时看到的变化：新增 2 条、修改 1 条、新材料 1 份 ▸ ("what the assistant saw had changed when it resumed this session: 2 items added, 1 changed, 1 new material"), and the full text opens with 接着这条会话继续时（time），上次之后交付物的变化： ("continuing this session, changes to the deliverable since last time"). When you stopped the assistant's work and open the session again before saying anything more, the folded line starts with 上次被停止 ("stopped last time"), and the full text has the sentence 上一次运行被用户停止，没有做完。 ("the last run was stopped by the user and was not finished"). The assistant reads the same content; only the opening and a few phrases are worded for it. A session in which nothing has been said is not kept once you open another session; opening its address again shows 找不到这条会话 ("this session cannot be found") with a link back to the task page. While the assistant is working in the session you are in, you cannot open a new session until it finishes this turn.

## 2 Talk with the assistant

The work view has three columns: the conversation, the items area (the deliverable, grouped by collection), and the side panel with three tabs: **Materials** (材料, the uploaded texts), **Document** (文档, generating documents) and **Revisions** (修订, the revision log, see section 3). A task whose definition asks for it gets one more tab after Materials: in a requirements task, **Overall analysis** (总体分析; **Domain notes**, 领域说明, in tasks created by 0.4) lists the items of that collection in groups, each with how it is linked to other items, and clicking one opens it in the items area. What the overall analysis is and how it is used is described under **Overall analysis** at the end of this section. For a Word material, the Materials tab has a line **按章节看引用** (sections and citations) under the file name: opened, it lists the material's sections with their headings, paragraph ranges and how many items cite them; a section that no item cites is greyed with 还没有条目引用这一段, and clicking a section scrolls the text to it. Select a passage in a material and a bar floats just above it: **据此新建条目** (create an item from this), **补到当前条目** (add to the open item; shown only when an item is open in the items area) and **就这段提问** (ask about this passage). Each sends a sentence with the passage to the assistant, so it takes a while; with 就这段提问 the bar turns into an input box, and **发送** (Send) sends your question. A click elsewhere or Escape closes the bar. **Collapse** (收起) folds the side panel into a narrow strip; on narrow windows it starts folded. **Font size** (字号 小 中 大) in the top bar makes all text smaller or larger; text also scales with the window width, and the choice is kept in the browser. The colours and the typeface of titles are changed in the settings; see section 11.

**Reading a PDF in the Materials tab.** A PDF material is shown in the Materials tab page by page, as it is. The line with the file name says how many pages it has; when some pages have no readable text (usually scanned images) it also says 其中 N 页没有可读的文字 ("N of them have no readable text"), and each such page carries a note at its top: the assistant cannot read that page and items cannot cite it. A line of small print below reminds you that tables in a PDF are read row by row, not cell by cell. Under it is the **目录** ("contents") line, closed by default; opened, it is a list: when the file has its own bookmarks, each entry with its title and page, and a click jumps to that page, with the entry of the page you are looking at marked (none is marked when more than one bookmark points to that page); when it has none, it says 这份文件没有目录 ("this file has no table of contents") and lists the pages instead. The bar above the pages shows the current page and the page count, and on the right **缩小** (smaller), **放大** (larger), **适应宽度** (fit the width) and the current scale; a file opens fitted to the width of the tab, so in a narrow tab the print is small and you may want to enlarge it and scroll sideways. However long the file is, only the pages in view are drawn, as you scroll to them. Click a source of an item that comes from a PDF (its label reads file name · 第 N 页, "page N"; the chapter follows when the file has bookmarks and the page can be told to belong to one of them, and is left out when more than one bookmark points to that page): the tab scrolls to that page, an orange frame marks the block the source points to and the excerpt is marked character by character; the marking fades after two seconds and the frame stays until you click another source. When the excerpt runs on from that block into the following ones, all of them are framed and a line above says so; when the excerpt is not found in the block, or its characters do not match the page, only the block is framed and a line above says why. Sentences cited by an item have a light blue underline; click one to open the item that cites it. Selecting a passage brings up the same action bar as described above. When the page itself cannot open a PDF (for example because it is password-protected), or cannot draw one of its pages (usually because the browser is rather old), it shows the file in the browser's own PDF viewer instead, with the line 这个浏览器里只能按页显示，不能标出摘录。 ("in this browser the file can only be shown page by page; excerpts cannot be marked") above it: clicking a source or an entry of the contents then only jumps to the page, no block is framed, no excerpt is marked and cited sentences are not underlined; what the assistant reads and the sources of the items are not affected. In the task page's list of materials a PDF has its page count, and the number of pages without readable text, after its name, and **查看** (View) shows it page by page as well. While a PDF is being uploaded the page shows 正在上传……PDF 要先读出各页的文字，页数多的要多等一会儿。 ("uploading… the text of each page has to be read first; a file with many pages takes a little longer"), and that line turns into the result when the upload is done. A source that comes from a PDF document of a knowledge base is labelled library name / document name · 第 N 页; opening it still shows the text of the document, not its pages.

Tell the assistant what you want, for example *"请读 inputs 里的材料，整理成需求规格说明。"* It reads the materials, writes items, and replies. Each reply lists what it just did, then says what it needs from you. When it needs you to do something, the reply ends with a card:

| Card | What it asks | Your options |
|---|---|---|
| Question | an open question | type your answer; if the question is about items, **Keep pending** (暂不处理这条, only for items in the issues collection, 问题) or **I don't know, fill in from common sense** (我不知道，你按常识补); if it is not about any item, **I don't know, fill in from common sense** or **Set aside** (暂不处理: leave the question unanswered and let the assistant go on) |
| Choose | pick one of several answers | click an option, or type your own |
| Look over (请过目) | asks you to look at these items as they are now (used only when the assistant really needs it). It does not ask for your agreement: for that the assistant uses a proposal or a choice | **I've read these** (这几条都看过了), which marks the items as read, or **Not right** (不对, optionally with what is wrong). Each item line shows its current revision and whether you have read it, for example 修订 9（已读）("read"), 修订 9（未读）("unread"), or 修订 9（已读 · 你看过修订 4，之后又改过）("read · you read revision 4, changed since") when you read an earlier revision. |
| Suggestion | a proposed value with its basis | **Adopt** (采纳) or **Another one** (换一个) |
| Proposal | a plan, with what it would add, change or remove | **Do it** (就这样做) or **Don't** (不要) |

After you answer an issue item, the assistant first changes the items it concerns, then asks with a choose card whether the issue is settled, with the options 已解决 ("resolved"), 还没解决，继续改 ("not yet, keep changing") and 先不管，保留 ("leave it for now"). When the assistant marks an issue resolved, it also records where the answer was written (which page, item or diagram). The issue is marked resolved or kept by your decision only after you click 已解决 or 先不管，保留 on that card; if you type that it is settled, the assistant still sends the card for you to click. If the issue or the items it concerns change after your click, the assistant asks again. Clicking **Keep pending** (暂不处理) on the item yourself still takes effect at once.

You can always type instead of clicking; you do not have to answer the card first. If the options don't include what you know, say it in your own words.

**A card can wait.** There are two places to type. Each card has a text box of its own (with the hint 或者直接告诉我你的想法…, "or just tell me what you think"); what you write there answers that card, and the card closes with 你在卡片里回复了 ("you replied in the card"). The input box at the bottom of the conversation is for anything: when you say something else there, the card does not close, its buttons and text box stay usable, and you can come back to it at any time; when what you say there does answer a card, the assistant recognises it from the context, and after its reply the card closes with 你回答了这张卡片 ("you answered this card"). The assistant does not press you about questions and choices you set aside. Before it proposes the next stage it asks each one still unanswered in the current stage again, one at a time (the earlier card closes with 这个问题在后面重新问了, "this question was asked again later"); if you still do not want to answer, say you do not know or that it can wait, and the assistant records it as an issue item before proposing the next stage.

After changing items the assistant only tells you what it changed; it does not ask you to confirm. You confirm an item by reading it: opening its details counts (see section 3). Before asking whether to complete the task, the assistant tells you how many items you have never read. When nothing but unread items stands in the way of completing, a live card also shows 还有 N 条未读 ("N items still unread") with **Show them** (筛出来看), which filters the list to the unread items.

**One at a time.** Only one party changes the deliverable at any moment:

- **While the assistant works**, a banner at the top of the items area says 助手正在工作，结束后你可以继续修改 ("the assistant is working; you can continue editing when it is done"). Every write button on the items (edit, save, delete, mark as read, keep pending, undo) is greyed out, and hovering over a greyed-out button tells you why, and the send button is greyed out too: one message starts one piece of work, and the next message waits until it is done. You can still type; your draft stays in the input box. **Let the assistant change this one** (让助手来改这一条) and **Answer this question** (回答这个问题) stay available, because they only prefill the input box. The HTTP API refuses messages and direct operations sent during this time with `session_busy`. Opening an item's details still marks it as read, because that does not change the deliverable.
- **While you have unsaved changes** in an item's editor (the editor is open and its content differs from when you opened it), the send button and the buttons on the conversation's cards are greyed out, with the hint 先保存或取消正在编辑的条目 ("save or cancel the item you are editing first"). Save or cancel, and they come back.

**Stopping the assistant.** While the assistant is working in the session you are in, the send key to the right of the input box becomes a stop key: the same place and size, with a small solid square in it, and the hint 停止助手这一次的工作 ("stop this piece of the assistant's work") when the pointer rests on it. Click it: the square fades and pulses (stopping), and this piece of work stops; what the assistant already saved stays. When the work has ended the key is the send key again. An unsaved edit of an item does not keep you from stopping. Pressing Enter in the input box does not stop the assistant; only a click on the square does. When the assistant is working in another session the key here stays the greyed send key; stop the assistant in that session. The `stop` control request of the HTTP API does the same ([api.md](api.md), section 5.5). After a stop, under the summary line of that turn (助手做了 N 步，用了 X, "the assistant took N steps in X") an amber line says what this piece of work actually saved: 这一次工作保存了修订 3 到 5（4 个条目、1 张图），都保留着；停下时正在做的那一步没有完成。要撤销其中某条，到右侧「修订」页签逐条撤销。图的改动不能撤销，可以让助手改回去。 ("this piece of work saved revisions 3 to 5 (4 items, 1 diagram), and they all stay; the step in progress when it was stopped was not finished. To undo one of them, undo it in the Revisions tab on the right, one at a time. A change to a diagram cannot be undone; ask the assistant to change it back"). This is looked up in the task database after the stop, so a revision that was being written at the very moment of the stop is counted too. The sentence is shorter when only one revision and no diagram was saved; when nothing was saved the line is only 这一次工作没有保存任何东西。 ("this piece of work saved nothing"). A stop takes nothing back: undoing is done only by you, revision by revision, in the Revisions tab. A 产生了修订 N tag under the line opens those revisions in the Revisions tab. A turn that stopped because of an error gets 这一轮因为出错停下了，助手没有做完。已经保存的修订保留着；你可以再说一句，让它接着做。 ("this turn stopped because of an error and the assistant did not finish; saved revisions stay; say something more to let it continue"), and a red notice in the top right corner says the same briefly. The line is still there after you reload the page. A turn you stopped has one more line under it, 你停止了助手这一次的工作 ("you stopped this piece of the assistant's work"); from it the assistant knows at its next piece of work that the last one was not finished, so say one more sentence if you want it to carry on.

When a piece of work produced revisions, a small tag at the bottom of the reply says so, for example 产生了修订 8、9 ("produced revisions 8, 9"). Click it to open those revisions in the Revisions tab.

## 3 Work with the items

Every save of the deliverable is a **revision**, numbered from 1 within the task: each save by the assistant and each direct operation of yours (edit, delete, keep pending, undo) creates exactly one. Items have no version numbers of their own; an item "is at revision N" when N is the last revision that added, changed or restored it. Marking as read does not create a revision.

Each item carries at most one coloured status badge, saying what the item still lacks. When several things are open, only the first of these is shown: 评审不通过 N 处 ("failed review, N problems", red), 未读 ("unread", amber), 待评审 ("waiting for review", grey), 评审不通过 N 处 · 已保留 ("failed, kept", green outline: you kept the wording, so it counts as passed) and 问题 N 未解决 ("N open questions", amber). An item that lacks nothing has no badge. Hover over the badge to see the whole state: the review result, the revision you last read and the number of open questions. Collections that are not reviewed (issues, and the overall analysis or the domain notes) never show the three review badges. Unread rows are in bold like an unread e-mail. The rest is small grey text: the category, 修订 N once the item has changed more than once (修订 N · 刚改 in bold when the assistant's last piece of work changed it) and 有助手补充的内容 ("has content added by the assistant"); rows of collections like the overall analysis also show the number of sources, which for the other collections is shown below the item's details header. The details header shows the same badges, and below them one grey line such as 已读 · 现在是修订 4，由助手写的 · 来源 3 条 ("read · now at revision 4, written by the assistant · 3 sources"). Click an item in the list to see every field and where each part came from. **Opening the details marks the item as read, and reading counts as confirming**; there is no confirm button. Only opening the details counts; seeing an item in the list does not. Read is per item: once you have read an item it stays read, even if the assistant changes it later. The four kinds of source tag are:

- **Document excerpt** (材料原文): a verbatim quote from a material, with the file it came from; click it to see the sentence highlighted in the Materials tab (an excerpt made of several passages is highlighted passage by passage, scrolled to the first one); when none of it can be found in the material, the top of the Materials tab says 没有在材料里找到这段原文 ("this passage was not found in the material") for two seconds. A Word material is shown page by page in its original layout, and its excerpts are labelled with the page, the section and the position on the page, for example `requirements-styled.docx · 第 3 页 · 3.1.1 逾期罚款 · 页下` (page 3, section 3.1.1, lower part of the page); the section is the nearest heading at or before the cited paragraph, with its automatic number as Word shows it, for example 第一章 总则, and a heading inside a table does not count; an excerpt that runs over several paragraphs has all of them marked and the tab says 这段引用跨越了多个段落，已整段标出 ("this quote spans several paragraphs, all of them are marked"). Text in headers, footers, text boxes, footnotes and endnotes can be read but not quoted; comments are not shown and tracked changes are shown as accepted;
- **Knowledge base** (知识库): a verbatim quote from a document in one of the knowledge bases the task uses. The label is magenta and the locator reads "library name / document name" (with the paragraph for a Word document); click it to read the document in a read-only dialog with the quote highlighted. When the document has been deleted from the knowledge base the source stays, the locator cannot be clicked and 这份文档已经不在知识库里 ("this document is no longer in the knowledge base") is written beside it. Knowledge base documents are reference material: they do not appear in the Materials tab and are not organised into items;
- **Your words** (用户的话): something you said in the conversation;
- **Added by the assistant** (助手补充): something it inferred or filled in. The source holds the reason, shown after 理由： ("reason:"); the assistant cannot save such a source without one;
- **Item** (条目, written as 条目 OA-002 followed by its title): another item already recorded in the task, for example a use case resting on a topic page of the overall analysis, or a constraint resting on a use case; click the id to open that item. When the cited item has been changed since, the source is marked 依据已变：OA-002 在这之后改过（引用时是修订 2，现在是修订 5） ("the basis has changed: OA-002 was changed after this; revision 2 when cited, revision 5 now"), a reminder to check whether this item still holds; the mark goes away once the assistant has checked and written the source again. When the cited item has been deleted the source says OA-002 已经删除 ("OA-002 has been deleted"). An item that other items rest on has a line 被谁依据 ("cited by") at the bottom of its details, listing them; click an id to open it. The details of a topic page of the overall analysis (of a domain note in tasks created by 0.4) have the fuller section 被哪些条目引用 ("which items cite it"). Collections that are not reviewed, such as issues and the overall analysis, show no review state in the items area or on the task page;

**Overall analysis.** From this version on a new requirements task has a central collection, the overall analysis (总体分析, ids starting with OA), in place of the earlier domain notes. It holds everything you and the assistant worked out about the concepts, roles, processes, scenarios, goals, assumptions and decisions of the matter, written in the matter's own words. One item is one **topic page**: a title and aliases; 它是什么 ("what it is", one or two paragraphs); 例子 ("examples": a named person, a concrete thing, a concrete day; an example of what does not count starts with 反例：); 已经定下的 ("settled": one sentence each, each with its source); 标签 ("labels": 概念, 角色, 流程, 场景, 目标, 范围, 假设, 决定, meaning concept, role, process, scenario, goal, scope, assumption, decision; a page may have none); a parent topic, a state (在用 "in use" or 已废弃 "retired") and the page to look at instead. The assistant picks up a word you have not explained and starts a page with a candidate explanation and example, asks for examples and exceptions, points out conflicts between pages, and retells its understanding as a short story for you to check. Use cases, requirements and constraints are written with topic pages as their basis.

- **Waiting to be verified (待核实).** A page with content the assistant added and you have not confirmed is waiting to be verified. Clicking **确认待核实的 N 处** ("confirm the N places waiting to be verified") on the page confirms the whole page (just opening a page that is waiting does not); editing it yourself confirms only the places you changed. When the assistant changes it again, it waits again.
- **Topics first, then items.** The assistant can start writing use cases, requirements and constraints only when the task has at least one topic page in use that has a label, has an example and has been looked at by you, and you have chosen 开始写条目 ("start writing items") on the card the assistant sends; so in a new task the assistant first writes topic pages and asks you to read them.
- **Only labelled topics reach the document.** Pages labelled 概念 go into the terms section, the others into the general description by label; a page without a label is a draft, and a retired page is left out.
- **On the page.** **业务说明** (business description, the name the page gives to the overall analysis collection) is the first tab in the row above the items area, and a task with no other items opens on it; after that the page remembers the tab you were on (in this browser, for each task separately). The tab shows the **contents** (目录) on the left and one section or one chapter page on the right:
  - The **contents** always have seven chapters: 概述与范围 (overview and scope), 角色 (roles), 业务流程 (business flows), 业务对象 (business objects), 业务规则 (business rules), 业务目标 (business goals) and 决策记录与待澄清事项 (decisions and open questions). A topic page is one section and goes into a chapter by its labels: 范围 and 假设 into chapter 1, 角色 into chapter 2, 流程 and 场景 into chapter 3, 概念 into chapter 4, 目标 and 决定 into chapter 6; a page with several labels goes into the earliest of those chapters. Sections are numbered in the order of the chapter (3.1, for example) and a sub-section is indented; a retired section is struck through and has no number; pages without a label are listed last under 未归类 (not sorted). The introduction page of a chapter (added by the assistant in the document stage, see section 12) is not a section and has no number; in the contents it is a line 导语 ("introduction") before the sections of its chapter. The dot before a line is the state of the section (green: settled; amber: has content the assistant added, waiting to be verified; violet: has open questions). The foot says how many sections there are, how many requirement items and how many open questions. Click a section to open it, and a chapter title to open the chapter page; this is the same for all seven chapters. Chapter 3 has many sections, so a small triangle beside its title folds and unfolds them. The last section of chapter 4 is the **术语表** (glossary). **收起** folds the contents into a handle on the left, and clicking the handle unfolds them; when the items area is narrow the contents start folded and open over the content on the right.
  - A **section** starts with its chapter, its number and its title; the line under the title says how many places of the materials and how many clarifications it cites and whether you have looked at it, followed by its labels and how many places wait to be verified. The blocks below come in a fixed order, and a block without content is left out: **说明** (description; a sentence taken word for word from a material is highlighted and opens the material on the right when clicked, words the assistant added are marked in amber, and the sources are at the end), **流程步骤** (flow steps: the flowchart of this section), **状态图** (state diagram) and **与其他对象的关系** (relations to other objects; only in sections of business objects, the latter being the whole object relation diagram with the object of this section outlined), **异常分支** (exception branches: the examples that start with 例外：, one small card each; a flow section ends the block with **＋ 补一种例外**, add an exception), **示例** (the other examples; a counter-example says 这种不算), **适用规则** (applicable rules, one per line with its source; a rule that conflicts with another says which section it conflicts with), **待澄清事项** (open questions attached to this section, with why each is needed; write an answer and click **记下** to send it to the assistant, or **暂不处理** to leave it unanswered), **其他图** (other diagrams), **相关角色与对象** (the roles, business objects and flows related to this section; click one to open it) and **对应的需求条目** (the requirement items written from this section, each with a state: 草稿 draft, 评审中 · N 处发现 in review with N findings, or 已确认 confirmed). The last line, **追溯** (trace), goes from the materials and the clarifications through the diagrams to the items, and every part of it can be clicked; its last part gives the number of the section in the generated document (the same as in the contents).
  - What you can do in a section: **确认待核实的 N 处**; **修改** (edit, with every field in a form); **＋ 标签** (labels, which decide the chapter); and at the foot **让助手照这条改条目** (only fills a sentence into the input box of the conversation, for you to send), **标为已废弃** (retire) and **复述一遍** (retell). After 复述一遍 the assistant tells what it has understood as a story in the conversation, with three options: **采纳为例子** (take it as an example: the story is recorded as an example on that page), **有误，需修改** (something is wrong and needs changing) and **换一个例子重述** (retell it with another example). The small line at the very bottom, **看修订与全部来源**, shows the same page the way an item's details are shown, with its revisions and all sources.
  - **Chapter pages.** When a chapter has an introduction, it is shown at the top; below it each section of the chapter is summed up (number, title and the first paragraph of its description; click to open the section), and in chapter 3 each section also says how many use cases are based on it. Chapter 1 shows the system boundary diagram, the top two levels of the goals and the full description of every scope and assumption section. Chapter 2 shows the table **角色与用例对照** (roles and use cases): one column per role, one row per use case, in each cell the text written on that edge of the use case diagram (参与, "takes part", where the edge has no text), and in the last column the flow the use case belongs to; the line under the table names the use case diagram it was built from, and **查看用例图** opens that diagram. Chapter 4 shows the whole object relation diagram. Chapter 5 is the **规则表** (rules table), which gathers the applicable rules of all sections; rules that conflict are highlighted and a line above the table says how many pairs conflict. Chapter 6 is the goal tree, with the decisions under each goal and why they were made. Chapter 7 lists the decisions and the open questions by time, and a row opens the section it belongs to. The other chapter pages list the first paragraph of each section.
  - An item based on a topic that waits to be verified or is retired has a small amber label on its line in the item list, 依据的主题待核实 or 依据的主题已废弃; hovering says which page it is and what to do. When it is based on a diagram you have not looked at yet, the label reads 依据的图还没有看过. In the sources of an item's details, the id of a topic page opens that section, and the id of a diagram opens the section that holds the diagram.
  - The **业务说明** tab of the side panel is a short list for looking things up while reading items: only labelled topics, grouped by label; clicking a line opens the section in the items area.
- **Tasks created by 0.4 are unchanged**: they keep their domain notes and work as before, without the "topics first" requirement.

In tasks carried over from 0.4.1, sources that were labelled 领域说明 are now labelled 条目, and 助手补充 stays as it was. An item that cited a domain note before the upgrade, where the note was changed afterwards, shows 依据已变 straight after the upgrade.

When the assistant changes an item, its existing sources stay. Each entry of a list is recognised by its content: after the assistant inserts, removes or reorders entries, a source still points at the same sentence, and a source pointing at an entry that was removed goes with it. When the assistant rewrites an entry or a field, its existing sources stay as well; if the assistant finds that one no longer supports the new content, it relabels the item's sources to remove it. When you edit an item yourself on the page, the sources of the entries you did not touch stay and follow their entries in the same way; a sentence you rewrote (a field, or one entry of a list) loses its earlier sources and gets no new one: what an item says counts as your own, and who changed what is shown by the revisions. When an item has no sources, the 来源 (sources) section is left out of its details.

The drop-down at the top right of an item lists the revisions in which it changed; choose one to see the item as it was then, with the differences from its previous change marked. If the list of revisions could not be loaded, the drop-down says 修订列表没读到，再打开一次试试 ("the revision list did not load; open the item again"); go back to the list and open the item again.

**What the assistant changed since you last confirmed.** Fields the assistant changed since the revision you last confirmed (or since the item was added, if you never confirmed it) are framed with an amber left border, and the note at the top says 与你上次确认的修订 K 相比，改了这几处 ("compared with revision K, which you last confirmed, these places changed"): struck-through text is how revision K put it, underlined text is how it reads now. Changes accumulate across several revisions. Fields you changed yourself are not framed. Because opening the details marks the item as read, the frames are fixed when you open it: they stay while the details are open and are gone the next time you open the item. The frames and 刚改 only point out what the assistant changed; they do not affect whether the item is read and do not block completion. Items changed by the assistant's most recent piece of work are marked 修订 N · 刚改 ("revision N · just changed") in the list.

You can act on the item directly with the buttons under it: **Edit** (修改) opens the fields for editing and **Save** (保存) saves them as a new revision; **Delete** (删除) removes the item; **Keep pending** (暂不处理) sets an issue item's status to kept by your decision. The bottom right of the item only shows its status; reading cannot be withdrawn. An issue item cannot be edited directly once it is written: its details only offer **Keep pending** and **Delete**. To answer it, tell the assistant in the conversation; it changes the items the issue concerns and then asks you whether the issue is settled. Saving your own edit, or keeping an issue pending, also counts as confirming that item. Tick several items in the list and click **Mark these as read** (把选中的这几条标为已读) to mark them together. **‹ Back to list** (‹ 回到列表) returns to the list. Every change creates a new revision; nothing is overwritten.

**Questions follow the items they concern.** An issue item's related items (关联条目) tie it to those items. In the list, an item that unresolved issues point at carries an amber **问题 N** badge ("N questions") next to its status badge; it counts only unresolved issues and disappears at 0. When the questions are the only thing an item still lacks, its one badge reads 问题 N 未解决 instead. An issue item itself only shows its own status: 未解决 (unresolved, amber), 已解决 (resolved, green) or 用户决定保留 (kept by you, green outline). The item's details open with **挂在这条上的问题** ("questions on this item"): one card per unresolved issue with its kind, status, text and the assistant's suggested handling; when no unresolved issue concerns the item, this part is not shown. On a card, type your answer and click **Answer** (回答): the conversation receives "回答 TBD-002：<your answer>" and the assistant changes the items the issue concerns; with the box empty, **Answer** only prefills the conversation input. **Keep pending** (暂不处理) works as elsewhere. Resolved and kept issues are not shown on the item, and a card you keep pending disappears once the change is saved; they remain in the Issues tab, and the Revisions tab shows how each one was settled. With the box empty, **Answer** only prefills and sends nothing, so it is greyed out only when the task has ended or the assistant is unavailable; it stays available while the assistant works and while an item edit is unsaved. With text in the box, clicking it sends that text at once, so it is then also greyed out like the conversation's send button: while the assistant works or while an item edit is unsaved. **Keep pending** is a real write and is greyed out like the other write buttons: when the task has ended, when the assistant is unavailable, while it works and while your previous change is being saved; an unsaved item edit does not grey it out. On the question cards in the Issues tab, **Answer this question** (回答这个问题) only prefills and is greyed out under the same rules as **Answer** with an empty box. Hovering over a greyed-out button tells you why. Clicking a related item on an issue card in the Issues tab opens that item with **‹ Back to the question list** (‹ 回到问题列表) at the top. If that issue is unresolved, its card comes first and is highlighted, and the other issues fold into one line **还有 N 个问题 ▸** ("N more questions") that opens on a click. If it is already resolved or kept, the line at the top is the same, its card is not shown, and the other unresolved issues are listed as usual. Issues without related items stay only in the Issues tab.

If the same item is open in two browser tabs and one of them saves first, the other tab's save is refused: a red message at the top right says the item has been changed to revision N, and stays until you close it. Nothing is merged; click **打开最新** ("open the latest") in the message to leave the edit and see the current content, then make your change again.

**Messages at the top right.** Things that just happened are reported in one place, the top right of the page, newest on top and at most three at a time: success (green, fades after 4 seconds), in progress (blue, with a progress bar, replaced by the result), warning (amber, fades after 8 seconds and comes back while the situation lasts, for example while the connection to the server is lost) and failure (red, stays until you click ×). Hovering over a message pauses its timer. Some messages end with an action, such as 打开最新 or 看评审页签 ("open the Review tab"). A message you sent that could not be delivered also stays in the conversation, marked as not sent, and its text is put back into the input box it came from if that box is still empty, so you can send it again; if you have already typed something new, your new text is kept.

**Lost connection, stopped service.** When the page loses its connection to the service, the warning at the top right says that your changes cannot be sent until it is back; the page reconnects by itself and then catches up on what changed meanwhile. After about a minute without a connection the warning becomes a red message that stays, 连不上服务，可能已经停止。你可以稍后刷新这个页面再试。 ("cannot reach the service, it may have stopped; refresh this page later"), and the page tries every 30 seconds; the message goes away once it is back. When the page reaches the service through a forwarding layer (a reverse proxy, for example) and the service is stopped or restarting, opening or reloading a page and actions on it show 连不上任务服务，可能正在重启。请稍后再试；一直不行，请告诉管理员。 ("cannot reach the task service, it may be restarting; try again later, and tell your administrator if it keeps failing"). When the service is stopped normally, open work views switch to a full-page notice, 服务已退出，可以关闭此窗口 ("the service has exited, you can close this window", desktop packages) or 服务已停止。恢复之后刷新这个页面即可继续。 ("the service has stopped; refresh this page once it is back", server), and stop reconnecting.

**The assistant has exited.** When the assistant has exited but the service is still running, a blue note above the input box says 助手已经退出，下一次说话时会重新启动。 ("the assistant has exited and will restart the next time you say something"). The page stays usable: saying something, clicking a card button or editing an item makes the service start the assistant again in this session first; for those few seconds the note says the assistant is starting and the send button is unavailable. If the service could not resume this session after a restart, the note says so in the same way and does not block anything either. Only when the assistant cannot be started at all (for example no model is set up) does the page become read-only, with the reason shown.

When the assistant changes an item you had read, the item stays read; the list marks it 修订 N · 刚改 ("revision N · just changed") and its details show the changed fields, and it is up to you whether to look again. The line 还有 N 条未读 · 筛出来看 ("N items unread · show them") above the list, and the **Unread** (未读) filter, list the items you have never opened.

**The Revisions tab** (修订) lists every revision of the task, newest first. Each card shows 修订 N · time · 助手 (the assistant) or · 你在界面上改的 (changed by you in the interface), what triggered it: 因为你说：纠正：UC-003 的参与者改为借还台管理员 ("because you said: correct: …") when the assistant recorded its understanding of your message and the revision matches one of the acts in it, otherwise which of your messages it answered, which card you clicked, or which direct operation you made, and one line per item it touched: added, changed, deleted or restored, and which fields changed, with **Show changes** (查看差异). Click a card to highlight the items it touched in the items area; the collection tabs show how many, and 修订 N 碰到的条目 ✕ in the filter line clears it. **Undo this revision** (撤销这次修订) creates a new revision that puts every item of that revision back the way it was (a deleted item comes back, an added one is deleted). If one of those items has changed again since (or has been deleted), the revision cannot be undone: the button is greyed out beforehand, and hovering over it says 这次修订碰到的条目之后又改过，不能撤销；要改请直接改条目 ("an item this revision touched has changed since, so it cannot be undone; edit the item directly instead"). **Generate a document from this revision** (按此修订生成文档) opens the document dialog for that revision. The tab stays readable while the assistant works; only undo is greyed out.

**Review.** Items in the use case, non-functional requirement and constraint collections must pass review before the task can be completed. You start the review: **Review N items waiting for review** (评审 N 条待评审的条目) at the top of the items area reviews every item that has no review at its current revision, **Review this item** (评审这条) in an item's details reviews that item, and **Review these N** (评审这 N 条) in the completion conditions reviews the items listed there. The buttons are greyed out while the assistant works. The review runs in the background, about ten seconds per item and four at a time, and you can keep working: a blue message at the top right shows 评审中 3/12 ("reviewing 3 of 12") with the items being reviewed, and turns into the result with a link to the Review tab when the review ends. If the assistant's program exits in the middle of a review, the note goes away and the review buttons can be used again, so you can review once more. The reviewer checks each item against numbered rules (for example UC-R7). A finding under a required rule is a **problem** (red) and fails the item; a finding under an optional rule is **advice** (amber) and does not. An item that passes shows a green note under its title in the item detail, for example 评审通过：按 14 条规则逐条核对，没有发现问题。 ("passed: checked against 14 rules one by one, no problems found"), with the time of the review and the revision on a second line; 看这 14 条规则 ("see these 14 rules") lists the rules it checked with their numbers and text. Rules switched off for this task are not in the list, and a grey line at its end says how many are off. In the Review tab, **核对了哪些规则** ("which rules were checked") after a passed item shows the same sentence and rules. When the rules changed after the review, the rules it checked cannot be listed, and the note says 评审之后规则改过，这里列不出当时核对的规则。 ("the rules changed after this review; the rules it checked cannot be listed here"). Findings appear next to their fields; click the rule number after 违反 ("violates") to read the rule, and click **Let the assistant fix this** (让助手照这条改) to put a request into the message box. An item is reviewed once per revision and rule set: it waits for review again only after the item changes or the rules change. Until then **Review this item** is greyed out; for an item that failed, hovering over it says what you can do: change it as the findings say and review it again, or keep its wording. The **Review** tab (评审) in the side panel first says what needs your attention. Its top line says where things stand: 3 个条目还没有评审。 ("3 items have not been reviewed") with its one button **Review these 3 items** (评审这 3 个条目); after the rules change, 规则改过，3 个条目要重新评审。 ("the rules changed; 3 items must be reviewed again"); while a review started from the page runs, 正在评审，已经评完 2 个，共 5 个。 ("reviewing: 2 of 5 done") with a thin progress line under it (a review the assistant starts from the conversation shows no progress here); 有 4 处问题等你处理。 ("4 problems are waiting for you"); or, after a small green tick, 全部条目都已经通过评审。 ("every item has passed review"). Below it, **要处理的** ("to handle") lists the problems grouped by item, one card per item with its number and title: each problem gives its place, for example 基本流程 第 2 项 ("basic flow, entry 2"), what is wrong and, after 改法：("fix:"), how to fix it, with **Let the assistant fix this** (让助手照这条改), **Keep this wording** (保留这种写法) and 依据的规则 ("the rule it rests on"), which shows the rule's number and text. During a review, an item's problems appear as soon as it has been reviewed, after the ones already shown. With more than three items, the first three are shown in full and each further item folds into one line with its number of problems; click it to open it. **建议** ("advice", with 不影响通过 "does not affect passing"), **已经没事的** ("fine now": the items that passed, and those whose wording you kept) and **评审记录** ("review log": one line per review, newest first, such as 评审了 5 个条目：4 个通过，1 个有问题。 "reviewed 5 items: 4 passed, 1 has problems", ending with 由助手发起 when the assistant started it) stay folded until you click their titles. Problems that were fixed since, that were found under the earlier rules, or that were found before the item last changed are not shown: an item that changed after its review, or whose rules changed, counts as not yet reviewed. The tab's badge is the number of problems to handle, the same number as in the top line. **Keep this wording** opens a box for a reason, which may stay empty; **保留** (Keep) or Enter keeps it, **取消** (Cancel) or Escape closes the box. The wording is kept for the whole item: when the item has several problems, the box says that all of them will count as passed by your decision. The item then counts as passed by your decision; if the item changes, it must be reviewed again. It moves to 已经没事的 with its problems and your reason, and **Withdraw** (撤销保留) there undoes it. In an item's details, the second line of each problem shows its status and your reason and ends with **Keep this wording** (保留这种写法): click it, add a reason if you like and click **Keep the current wording** (保留现在的写法); **Withdraw** (撤销保留) on the same line undoes it. While the wording is kept, the item's badge reads 评审不通过 N 处 · 已保留. The last line of the tab, 评审规则（共 34 条，开着 32 条） ("review rules: 34, 32 of them on"), opens a panel from the right with the review rules, grouped by collection, each with only a switch, the number and the text; **关闭** (Close), a click on the strip to its left or Escape closes it. The switch shows each rule's state: green with a white lock is a required rule, which cannot be switched off; green without a lock is on and can be switched off for this task; grey is switched off. The page does not let you make a rule required. A rule made required earlier in this task shows as on, and the hover text on its switch says 这条规则已经升为必选，违反它算问题。 ("this rule has been made required; breaking it counts as a problem"); it can be switched off directly, which also withdraws the promotion, and when you switch it on again it is optional. Switching a rule sends the collection's items back to waiting for review; earlier reviews are kept. When a review ends, the conversation shows one line, 评审完成：X 条合规、Y 条不合规…, with a link to the Review tab. The filters 待评审 (waiting for review), 评审不通过 (failed review), 已保留写法 (wording kept) and 评审通过 (passed review) list the items in each state: 评审不通过 lists only failed items whose wording you did not keep, the kept ones are under 已保留写法, and 评审通过 lists only the items that really passed. The assistant does not review on its own; if you ask it to review in the conversation, it does so and tells you the results.

## 4 Finish and generate the document

The summary line above the item list (for example 12 个条目 · 待评审 4 · 评审不通过 1 · 已保留写法 2 · 3 条未读；问题 3 条未解决 ▾, meaning "12 items, 4 waiting for review, 1 failed review, 2 with the wording kept, 3 unread; 3 issues unresolved"; the failed figure leaves out the items whose wording you kept, which are counted in 已保留写法 N and left out when N is 0; each figure equals the number of items the filter of the same name lists) opens the completion conditions, and the task page lists them too. For the bundled task type, every collection must meet its conditions (for example, every use case has passed review, no use case is one you have never read, and no issue item is left unresolved). The review condition lists the items not reviewed yet, the items that failed, and the items that failed but whose wording you kept (they count as passed), with **Review these N** and **Open X** (打开 X) buttons. The assistant first tells you which items you have never read. A completed task is read-only and cannot be reopened, so completing it takes a click from you; typing something like 完成吧 ("finish it") in the conversation does not count. When all conditions hold at the end of the assistant's work, it asks on a Choose card whether the task is finished, stating the facts and what submitting means, for example 功能用例一共 3 个条目，都已经评审通过或者由你保留了写法，你也都看过了，没有未解决的问题。这个任务是否已经完成？提交之后交付物不能再改，仍然可以生成文档。 ("these 3 use cases have all passed review or had their wording kept by you, you have read them all, and no issue is unresolved; is this task finished? After submitting, the deliverable can no longer be changed; documents can still be generated"). The options are **已完成，提交交付物** ("finished, submit the deliverable") and **还没完成，继续修改** ("not finished, keep editing"). The assistant can complete the task only after you clicked **已完成，提交交付物** on the latest such card, and only if the deliverable has had no new revision since you clicked; otherwise it asks again. Reading, reviewing and keeping a wording create no revision and do not make it ask again. When the conditions become met through what you do on the page while the assistant is not working (for example the last review passes or you open the last unread item), a green bar at the top of the items area in the work view says 完成条件都满足了。 ("all completion conditions are met") with a question that also states the facts and what follows. The page works it out from the items, so it differs slightly from the card: a collection you must have read but that is not reviewed (the overall analysis, for example) is named with its count, as in 2 条总体分析你也都看过了 ("you have also read the 2 items of the overall analysis"); when there are issue items it says 2 个问题都已经解决或者由你决定保留 ("the 2 issues are all resolved or kept pending by you"), and when there are none it leaves that part out. The bar has one button, **已完成，提交交付物**. Clicking it asks for confirmation, 提交之后这个任务变成只读，交付物不能再改，仍然可以生成文档。确定提交吗？ ("after submitting, this task becomes read-only and the deliverable can no longer be changed; documents can still be generated. Submit?"), with **提交** (Submit) and **取消** (Cancel). After **提交** the task is completed without the assistant, and the conversation shows 界面操作（不是用户打的字）：用户在页面上确认这个任务已经完成，提交了交付物（修订 N）。任务已标为已完成，交付物不能再改，仍然可以生成文档。 The bar is not shown while the assistant works, or while this session has an unanswered card from the assistant asking whether the task is finished (saying something else in the input box does not answer it: the card stays open); after you click **还没完成，继续修改** on that card the bar shows again. If the deliverable got a new revision while the confirmation was open, nothing is submitted and the bar says 这次没有提交：你看到的是修订 N，交付物现在已经是修订 M。请看过现在的内容再提交。 ("not submitted: you saw revision N, the deliverable is now at revision M; look at the current content and submit again"). The bar is in the work view only, not on the task page. After completion the task is read-only; documents can still be generated.

Choose **Generate document** (生成文档) at the top of the items area, in the Document tab, on the task page, or on a card in the Revisions tab. In the dialog, choose one revision (the latest by default) and tick the items to include; the list shows the items that were in the deliverable at that revision. The whole document is rendered as of that revision, and the preview on the right follows your choice. The preview is laid out: headings, tables and lists are shown as such, and the diagrams are drawn. **Download Markdown** (下载 Markdown) saves the text file, and **Download Word** (下载 Word) saves the same content as a Word file, with the diagrams as images. You can generate the document at any time, also after the task is completed.

**The document has the structure of the business description on the page.** It opens with the task name, a note on the revision it was generated from, and the contents. The first seven chapters are the seven chapters of the business description, with the chapter and section numbers of the contents on the page: 1 overview and scope (the chapter introduction, the system boundary diagram, a summary of the goals, the scope and assumption sections); 2 roles (the roles and use cases table, the role sections); 3 business flows (one section per flow: description, flowchart, exceptions, examples, rules, open questions, the requirement items based on it); 4 business objects (the object relation diagram, the object sections, the glossary at the end); 5 business rules (the rules table); 6 business goals (goals and decisions); 7 decisions and open questions. Chapters 8 onward are the requirement items (functional requirements, non-functional requirements, constraints, issues), and the appendix 追溯 (trace) says which sections and diagrams each requirement item is based on. Pages without a label and retired pages are left out; a page you did not tick is not a section. Each item is marked with the revision its content comes from and whether it was confirmed and reviewed in that revision (a confirmation says on what basis: 已读 read, 用户修改 your own edit, or 明确确认 an explicit confirmation from an older version); unconfirmed and unreviewed items are included and marked as such. An open question is marked 【待澄清】 and a sentence that still carries 待定 is marked 【待定】. Pages and items are taken as of the revision, diagrams as they are now. The program lays the document out from what is in the task; no model rewrites it. Documents of tasks created before this version have this structure too. The [tutorial](tutorials/srs-authoring.md#act-6-take-the-document-and-look-back-at-what-the-agent-did) shows documents generated from the latest and from an earlier revision.

**Export to Word** (导出 Word), next to Generate document at the top of the items area, is a different thing: it does not produce the whole document but lays the items you tick out as tables in a Word file (the Word file of the whole document is downloaded in the Generate document dialog). Tick the boxes at the start of the rows in the item list; ticks are kept when you switch to another collection's tab, and the button counts the ticked items of all tabs, for example 导出 Word（3）. With nothing ticked the button is grey. Ticking and exporting change nothing, so both also work while the assistant is working and after the task is completed. The dialog says 导出选中的 3 个条目（来自 2 个集合）最新的版本。 ("export the latest version of the 3 chosen items, from 2 collections") and has one option, **带上来源** ("include the sources"), ticked by default; **导出** (Export) downloads the file, named after the task, 任务名-条目-date.docx. Every item is exported as it is now, also when it was changed after you ticked it; deleted items are left out. In the file the items are grouped by collection, the collection name as Heading 1; each item has a Heading 2 line with its id and title, from which Word can build a table of contents, and a two-column table of its fields: the entries of a list each on a numbered line, an empty field as （空）. With the sources included the last row of each table lists them, one per line, as kind · where it comes from：the excerpt. Chinese text is set in 宋体 (SimSun), Latin text and digits in Calibri, and the tables use Word's Table Grid style, so the content takes on the styles of the document you paste it into. Collections shown as cards, such as the issues, have no tick boxes and cannot be exported this way.

## 5 Try the example

`examples/library-lending/` contains a short, fictional requirements note for a school library ([`requirements.md`](../examples/library-lending/requirements.md)) and a script that runs the whole flow through the HTTP API only. With a task service running (see [deployment](deployment.md)):

```bash
examples/library-lending/run.sh http://127.0.0.1:8790
```

The script creates a task, uploads the note, opens a session, asks the agent to work, waits for its reply, and writes the generated document to `srs-<task id>.md` in the current directory. It needs only `curl` and `python3`, so it runs without the virtual environment. It prints the agent's progress every five seconds; with the default model a run usually takes one to three minutes and produces somewhere between ten and twenty items. The note deliberately leaves a few things open, so the agent has something to ask about.

The task it creates also appears in the web interface's task list, so you can open it there and continue.

## 6 Two ways to work with a task

| Interface | Command |
|---|---|
| Web (backend + browser interface) | `scripts/dev.sh`, then open `http://localhost:5680` |
| pi's own terminal UI | create the task in the web interface (or through the API), then `scripts/tui.sh tasks/<task id>` |

`scripts/tui.sh` starts pi's own terminal interface with the same startup profile the task service uses, so the assistant has the same tools, prompt, skills and model; type to talk and `/tw-board` to see the deliverable. It takes `--profile <name>`, `--label <name>` (sessions go to `$TASKWRIGHT_RUNS_DIR/pi-sessions/<name>/`, default `tui`), `--continue` (resume the latest session under that label) and `--session <file>`. When pi exits, it prints the session files it wrote. Scripted use through the HTTP API is described in [api.md](api.md).

## 7 See what the assistant did: the observatory

The observatory is a read-only local web app; it never changes any data. It reads the task databases and the archives the backend writes for every start of pi.

```bash
python3 -m taskwright_observatory --runs ./runs --workspaces ./tasks
# then open http://127.0.0.1:8770   (--port changes the port; Ctrl+C stops it)
```

- `--runs`: pass the task service's own `--runs` directory (`./runs` above). The service creates one archive directory per task in it (the directory that directly contains `pi-events/` and `pi-sessions/`), and the observatory takes in every one of them. It looks for them again on every read, so tasks created after the observatory started appear too, without a restart. To see a single task, pass that task's archive directory, `./runs/<task id>`. Repeat `--runs` to see several directories at once.

- Sessions run in pi's own terminal UI (`scripts/tui.sh`) produce no event archive and do not appear.
- `--workspaces` is the directory that holds the task directories (the service's `--tasks`). When it is left out, the observatory takes the `tasks/` directory next to `--runs` when `--runs` is the `./runs` level and such a directory exists, and the parent directory when `--runs` is a single task's archive directory.
- The observatory prints nothing when it starts; open the address above once the command is running.
- Files are re-read when they change: after a new session or a new task, refresh the browser.

The observatory's pages are in Chinese too; the table gives the tab names in parentheses.

| Page | What it shows |
|---|---|
| Sessions (会话列表) | one row per session: start and end, runs, turns, model requests, tool calls, rejected calls, outcome; each row links to its session details (进入会话详情) and its task page (进入任务页) |
| Tasks (任务) → task page | the task's history as stages; open a stage for the conversation and every change to the deliverable, open a turn for each tool call with its arguments, result and duration. The deliverable board shows each item's current revision, sources, review and confirmation (the review state follows the latest review of that revision: 评审通过 when it was compliant; 已保留写法 ("wording kept"), shown like a pass, when it was not compliant but you kept the wording after it; otherwise 评审过，没有通过 ("reviewed, not passed"). The observatory does not look at the rule fingerprint, so after the review rules change, reviews made under the earlier rules are still shown), and which completion conditions are still missing; click an item to see it in every revision in which it changed. The head has a line 对话 ("dialogue") with three facts: the assistant's acts still waiting for your answer, items the assistant asked about in two or more runs in a row without an answer, and fields changed at your request two or more times. Each run row shows its run number within the session (运行号 rN, not the same number as the row's sequence number across the task) and, when the run ended without a valid understanding of what you said, 这一轮没有合格的理解 ("no valid understanding this run"), at most once per run; an open run shows its dialogue acts, and in grey any JSON fragments the assistant wrote that matched no registered format or could not be parsed (diagnostics only, not failures), each with its first 200 characters and the validation or parse errors: your acts on the left (function such as 纠正（correct）, the items and fields, which assistant act it answers, how sure the assistant was, a summary) and the assistant's acts on the right, each marked 已回应（rN-M） answered, 等回应 waiting, or 不等回应 needs no answer. |
| Session details | the same view for a single session |
| System health (系统健康) | checks on the machinery: were the configured tools loaded, do the database rows match their events, were rejected calls later corrected |
| Concepts (概念对照) | what every term on the pages means |

A rejected tool call is marked where it happened; open the turn to read the reason the tool returned. With Langfuse configured, runs and tool calls also link to their Langfuse traces.

In a terminal, `python3 -m taskwright_observatory.dbshow tasks/<task id>` prints the task, its items with the revisions in which each changed and their sources, the revisions and the latest events; `python3 -m taskwright_observatory.check_db tasks/<task id>` checks that the database rows and events agree.

## 8 Test the language model in the settings

**First add model services, each for one purpose.** A model service provides one type of model: language models, which the assistant works with, or embedding models, which the knowledge base uses to search by meaning. On the settings page, under 模型 ("models"), press **添加模型服务** ("add a model service"): first choose which type of model it provides, then its kind, then fill in the address and the key. When one address provides both types, for example an ollama server with a language model and an embedding model, add it twice, with the same address and a different purpose. The list of model services is grouped into 语言模型 ("language models") and 嵌入模型 ("embedding models"), and each service's details name its purpose under 用途; when you change the language model only the enabled models of the first group are offered, and when you change the embedding model only those of the second. A model service that cannot tell the type of its models lists all of them, so enable only the ones of its type. If you upgrade from an earlier version in which one model service held both types, the task service splits it in two when it starts: the embedding models move to a service whose name ends in （嵌入模型）, and the models you had chosen stay chosen.

**Two things to do after upgrading from 0.4.0 (not needed again when upgrading from 0.4.1).** First, choose the language model in the settings. The desktop package no longer ships with a default model; while none is chosen the page says 还没有选定语言模型，助手现在不能工作。 ("no language model is chosen yet; the assistant cannot work") at the top, and 去配置模型 takes you to the settings page, where you add a model service and choose a model. Second, with a ChatGPT subscription, sign in once through the new entry: on the computer that runs the task service, open a command line, run `pi`, type `/login`, choose OpenAI in the list and sign in with the ChatGPT subscription as prompted. A login made through the earlier entry does not count; the Codex subscription's details then say 这一版改用新的登录入口，请重新登录一次 ("this version uses the new sign-in entry, please sign in again"). After signing in, go back to the settings page and press 重新检查 ("check again"), then 获取模型列表 ("fetch the model list"). The assistant does not go to the network by itself, so the catalog of models you can choose from does not renew itself; to update it, press 更新模型目录 ("update the model catalog") in the Codex subscription's details, which is the only time the network is used.

A configuration that was saved is not yet a model that works: a wrong key, a misspelt model name, a model service that runs but has not loaded the model, or an expired subscription only show when you talk to the assistant in a task. On the settings page, under **模型** ("models"), the row **助手用的语言模型** ("the assistant's language model") has a **测试** ("test") button to try it first.

Click **测试**; the dialog names the model that will be used. After **开始测试** ("start the test") the service starts the assistant once, the same way it does for a task, has the model read a small file and answer a question, and stops the assistant again. The file says how many boxes a shipment has, a number picked at random each time, and the model is asked 这批货一共有多少箱？ ("how many boxes does this shipment have?"), which it can only answer by really reading the file. **This sends one real request to the model service, and a commercial service may charge a very small amount.** The test is of the language model the assistant would use right now: the chosen one, or, when none is chosen, the one the row shows after 现在用的是 ("now using"). A test takes at most 90 seconds, and the language model cannot be changed while it runs.

The result appears below that row: 这一次测试通过，用时 N 秒。 ("this test passed, it took N seconds"), or 这一次测试没有通过： ("this test did not pass:") followed by the reason. Either way two more lines follow: 问模型：… ("asked the model: …") with the sentence the model was asked, and 模型回答：… ("the model answered: …") with what it said, or 模型没有回答 ("the model did not answer"). The reason is, for example, that the model did not call the tool that reads files, that its answer lacks the number of boxes written in the file, that the model service returned an error, that the test was not finished within 90 seconds, or that the model service has no key or is not signed in. The result is about this one test only: it is cleared when you change the language model or reload the page.

**The embedding model can be tested too.** The row **查找用的嵌入模型** ("the embedding model used for finding") has a **测试** button as well, which can be clicked once an embedding model is chosen. The dialog names the model that will be used. After **开始测试** the service has one sentence, 这批货一共有 N 箱。 ("this shipment has N boxes", the number picked at random each time), turned into an array of numbers; this test does not start the assistant. **This too sends one real request to the model service, and a commercial service may charge a very small amount.** A test takes at most 60 seconds. Only one of the two models can be tested at a time: while either test runs, **测试** and **更换** ("change") cannot be clicked on either row.

A test that passed shows three lines: 这一次测试通过，用时 N 秒。; 送去换算的话：… ("the sentence that was sent: …") with the full text that was sent; and 算出来的数字串长度：… ("length of the array of numbers: …"), how many numbers the model returned, which depends on the model, for example 1024 or 4096. A test that did not pass shows one line, 这一次测试没有通过： followed by the reason: for example that no embedding model is chosen, that the model service cannot be reached, that it rejected the key, that it does not have this model or has no embeddings endpoint, or that it answered with an error. The result is cleared when you change the embedding model (changing only the query prefix counts) or reload the page.

The sentence that was sent starts with the **查询前缀** ("query prefix") you entered under **高级** ("advanced") when choosing the embedding model, so this line lets you check the prefix. The prefix and the query are joined directly: no space, line break or colon is added for you, so write the prefix up to its very end. For a model that wants a task instruction in front of the query, such as Qwen3-Embedding, write the prefix as two lines: first `Instruct: Given a web search query, retrieve relevant passages that answer the query`, then only `Query:` with no line break after the colon. After a test that passed, these two lines are followed directly by 这批货一共有 N 箱。. Leave the prefix empty for a model that needs no instruction.

## 9 Embedding the knowledge base documents

The assistant searches the knowledge base in two ways at once, by meaning and by keyword. For the search by meaning every document has to be embedded with the embedding model first. While no embedding model is chosen, or some documents are not yet embedded, the assistant searches those documents by keyword only: the number of a rule or its exact wording is found, a passage worded differently is not, and the assistant tells you in its reply that this search was by keyword only.

**Where to look.** The document table on the knowledge base page has a column **换算** ("embedding"). Each document says **未换算** ("not embedded"), **等待换算** ("waiting"), **换算中** ("embedding", with the chunks done and the total in brackets), **已换算** ("embedded") or **换算失败** ("failed"); a document without text says 没有文字，不用换算 ("no text, nothing to embed"). The line above the table gives 已换算 N / M for this knowledge base (counting documents), a progress bar and the embedding model in use. While documents are waiting or being embedded the page updates itself every two seconds; there is no need to reload. When no embedding model is chosen the line says 还没有选嵌入模型，这些文档没有换算：助手查知识库只按字面找，用词不同的找不到。 ("no embedding model is chosen and these documents are not embedded: the assistant searches the knowledge base by keyword only and does not find a passage worded differently"), with the link **去设置里选** ("choose one in the settings").

**When documents are embedded.** A document uploaded after an embedding model is chosen is embedded automatically. Otherwise you start it: when an embedding model is chosen and this knowledge base has documents that are not embedded, the line above the table has a **开始换算** ("start embedding") button. After the task service restarts it does not carry on by itself; documents that were being embedded or waiting are 未换算 again, and **开始换算** starts them. Documents are embedded one at a time. Embedding sends requests to the model service, takes a while when there are many documents, and **a commercial service charges for it by use**.

**When it does not succeed.** A cause that concerns one document only (for example a paragraph longer than the model accepts at once): the document says **换算失败**, the line below it gives the model service's reason, and **重试** ("retry") is next to it; the other documents are embedded as usual. A cause that has nothing to do with the document (the model service cannot be reached, no answer in time, the key is refused): the whole run stops, the line above the table says 换算停下了： ("embedding stopped:") followed by the reason, and the documents stay 未换算; click **开始换算** once the cause is removed.

**Changing the embedding model.** Embeddings made by different models cannot be compared, so all documents have to be embedded again after a change. When the knowledge base already has documents, choosing another embedding model in the settings and clicking **用这个模型** ("use this model") asks first: 换了嵌入模型后，知识库里的 N 份文档要重新换算，换算完成前按意思查找暂时不可用。商业接口可能产生费用。 ("after the embedding model is changed, the N documents in the knowledge base have to be embedded again, and searching by meaning is unavailable until that is done; a commercial service may charge for it"). After **更换并重新换算** ("change and embed again") the choice is saved and embedding starts in the background; follow it on the knowledge base page. Choosing an embedding model for the first time asks in the same way. Changing only the query prefix needs nothing. Choosing **不用嵌入模型** ("no embedding model") does not ask, and the embeddings already made are kept: choosing the same model again later needs no new embedding.

**If documents were embedded with a build made before the 0.4.1 release, embed them once more after the upgrade.** Since 0.4.1 the embeddings stored beside a document also record where every chunk is in the original, so the file format has changed. After such an upgrade the documents embedded before all show **未换算** ("not embedded") on the knowledge base page; click **开始换算** ("start embedding") to embed them again. A commercial service charges for this once more. Until that is done the assistant searches these documents by keyword only.

**How the assistant uses the knowledge base.** The list the assistant gets at the start of each conversation gives, for every document in the knowledge bases the task uses, only its name, kind, size and how to write the locator when citing it; it gives neither the document's path nor its text. Whatever its size, a document is reached by searching. When the material hands the specifics to another document (for example 按公司规范执行, "as the company rules say", or 见术语表, "see the glossary"), the assistant must search; it searches for one thing at a time, by meaning and by keyword together: a passage is found even when the words differ, for example when the material says 超期不还 ("not returned in time") and the rules say 逾期 ("overdue"), and the number of a rule or its exact wording is found by keyword. What a search hands to the assistant is the verbatim original (a Word document one paragraph per line, a table cell by cell), and the assistant copies its excerpts from it; when a revision is saved the system checks each excerpt against the original character for character, relaxing only line endings and whitespace at the end of a line, and sends back what does not match. One search returns at most 5 chunks (3 when the assistant does not say), no more than 8 KB of text in all; when not everything fits the result says how many chunks are not listed and the assistant narrows the question. When nothing is found it searches once more in other words; if there is still nothing, a matter of public common knowledge or law is written into the item and marked as the assistant's own addition, and anything else keeps the material's wording with a problem item added.

The assistant's tool for searching files (`grep`) gives it at most 40 lines, about 6 KB, at a time: when there are too many matches the system cuts the result and asks for more specific words or several searches, for the materials and the knowledge base alike. When it reads a file of the knowledge base directly without saying how many lines, 120 lines are read. Both are caps, not blocks; the block on the knowledge base directory of the previous version has been removed. In the work view, the steps of the assistant say how many lines a search found and how many were looked at, and whether a knowledge base search was by keyword only.

To see for yourself whether something can be found, use **试一试按意思查找** ("try searching by meaning") under the document table on the knowledge base page (it lists the same chunks the assistant would get: besides the ones close in meaning, the first two by keyword are among them). Write one complete sentence and click **查找** ("search"): the closest chunks of this knowledge base are listed, each with its score (at most 1, larger meaning closer), the document name, the chunk's heading, where it is in the document and its text. Only the chosen knowledge base is searched here; the assistant searches all the knowledge bases the task uses. When no embedding model is chosen, or not every document of this knowledge base is embedded, the input is greyed out and the reason is written below it. A high score does not mean this is the rule you were looking for: it only says the meaning is close.

## 10 Diagrams

**Asking for a diagram.** In a task with stages, the assistant draws on its own when the task reaches the modeling stage: a system boundary diagram, a use case diagram, an object relation diagram, a flowchart for every flow page and a state diagram for every concept that has states. At other times it draws a diagram when you ask for one in the conversation, for example 把这几个用例画成用例图 ("draw these use cases as a use case diagram") or 给借书流程画一张时序图 ("draw a sequence diagram of borrowing a book"). There are six kinds: system boundary diagram (系统边界图: what the system exchanges with the people and systems outside it), use case diagram (用例图: who uses the system for what), object relation diagram (对象关系图: the things involved, their attributes and relations), state diagram (状态图: the states of one thing and what moves it between them), sequence diagram (时序图: who says what to whom, in what order) and flowchart (流程图: the steps of a process and where it branches). A diagram is written as Mermaid text. Before it is saved the text is checked; a text with a mistake is sent back to the assistant, which corrects it, so a diagram that is saved can be drawn. A diagram is not an item: it is not reviewed, needs no confirmation and does not count towards the completion conditions, and it is not part of the generated document or the Word export.

**Where the diagrams are.** In a task that has the overall analysis (a requirements task does), a diagram is shown in the business description at the place it describes: the system boundary diagram on the page of chapter 1; the use case diagram under the table on the page of chapter 2; the object relation diagram on the page of chapter 4 and in the section of every business object it draws; a flowchart under 流程步骤 in the flow section it draws; a state diagram in the section of the business object it draws; a sequence diagram or any other diagram under 其他图 at the end of the first section it draws. Which sections a diagram draws is read from the topic pages named in its sources; a diagram that names none cannot be placed in a section and is listed under **未归入节的图** (diagrams not in a section) at the end of the contents. Where several diagrams share a place, the one revised last is shown and **另有 N 张** switches to the others. Such a task has no Diagrams tab. A diagram has its own revision numbers, apart from the task's: 1 when it is drawn and one more for each change, so the Revisions tab and undo do not cover diagrams.

A task without the overall analysis (a task created by 0.4, or another task type) has no sections, so its diagrams stay in the **图表** (Diagrams) tab, the last tab above the item list: the number on it is the number of diagrams, each row has the id (D-001), the name, the kind and the latest revision, and clicking a row shows the diagram.

**One diagram.** Above the drawing are the name and the kind; point at the name to see the id and the revision. If the text cannot be drawn, the reason given by Mermaid is shown in its place. Drag with the left mouse button to move the drawing; hold Ctrl and turn the wheel to zoom in or out around the pointer (without Ctrl the wheel scrolls the page as usual). **缩小**, **放大**, **适应宽度** and **原始大小** (smaller, larger, fit to width, original size) do the same in steps, and the current scale (between 25% and 400%) is shown beside them. A diagram opens at a scale at which all of it is visible, but never below one half; drag to see the rest. The line under the drawing says which sections it was **画自** (drawn from) and which items are based on it (**被依据**), both clickable, and its revision. **文本与来源** at the upper right opens two tabs under the drawing, **文本** (text) and **来源** (sources); click it again to close them.

**Diagrams you have looked at.** When you see a diagram on the page (it has been drawn and is in the visible part of the page), the page records that you have looked at its current content; there is nothing to click. When the assistant changes the diagram afterwards, it counts as not looked at again. An item based on a diagram you have not looked at is marked as waiting, and its line in the item list carries the label 依据的图还没有看过.

- The 来源 tab lists the sources, which look like an item's sources. The sentence in which you asked for the diagram is one of them, and every item drawn in the diagram is another. When such an item was changed after the diagram was drawn, its source reads 依据已变：UC-002 在这之后改过 ("the basis has changed: UC-002 was changed after this"); when it was deleted, 已经删除 ("deleted").
- Below them, **图里画了谁** ("the items drawn in it") lists the item ids written in the Mermaid text, each with the item's title. Click one to open the item. An item that was deleted, or an id that is not an item of the task, is grey with a note.
- In an item's details the line **被谁依据** ("cited by") lists the diagrams that draw it; click a diagram's id there to open the diagram.

**Changing a diagram yourself.** Edit the Mermaid text in the 文本 tab. A moment after you stop typing the drawing follows the new text, under the note 预览：改动还没有保存 ("preview: the change is not saved yet"), and 文本与来源 carries a dot. Switching between the two tabs or closing them does not lose what you typed. **保存** (Save) makes the text a new revision of the diagram, made by you; **放弃改动** (Discard) goes back to the saved text. The text is checked before it is saved: a text with a mistake is not saved and the reason is shown under the text box, with the line it is on. If the assistant or another page changed the diagram in the meantime, your change is not saved and the message says which revision the diagram is at; discard, look at the current text and change it again. You are not asked for sources, and you may write an item id that the task does not have (it is listed greyed). While a change is unsaved, exporting and sending a message are unavailable, as with an unsaved edit of an item. While the assistant is working, and after the task is completed, the text is read-only. The assistant is told that you changed the diagram. On the page you can change only the text; ask the assistant to rename a diagram, change its note or kind, or delete it. A change to a diagram cannot be undone; ask the assistant to change it back, or edit the text again.

**Exporting.** **导出 PNG** (Export PNG) saves the drawing as a picture named after the diagram, for example D-001 读者用例.png, at twice the size shown at 100%, on a white background, whatever the scale and position you are looking at. A very large diagram is exported at a smaller scale, and a note beside the button says so. **导出 SVG** (Export SVG) saves the same drawing as a vector file with the same name and the extension .svg. It is drawn once more with HTML labels off so that the labels also show in viewers other than a browser. Fonts are not embedded in the file: it uses the fonts of the machine that opens it, so Chinese text may look different there.

A link can open one diagram directly: add `?diagram=D-001` to the address of a session. In a task with the overall analysis it opens the section or chapter page that holds the diagram and scrolls to it; in other tasks it opens the diagram in the Diagrams tab. With `?tab=diagrams` a task with the overall analysis opens at the first place of the business description that has a diagram, and other tasks open on the Diagrams tab.

## 11 Appearance in the settings: the interface style

The interface comes in two styles. Choose one on the settings page under **外观** ("appearance"), the second entry in the list on the left; the settings page opens on 模型 ("models").

- **暖纸** ("warm paper"): a cream paper background, dark grey-blue text, and page titles in a serif typeface. This is the style used until you choose one.
- **素白** ("plain white"): black, white and grey, with titles in the same typeface as the text. This is how earlier versions looked.

Each style has a card with a small preview (the paper colour, a top bar, a line of text, a rule and a primary button), and the card of the style in use says 现在用的 ("in use"). Click a card and the page changes at once; there is nothing to save and no need to reload.

A style changes colours and the typeface of titles only; nothing on a page moves or changes size. It is independent of **Font size** (字号 小 中 大) in the top bar, and you can set each on its own. The choice is kept in this browser: in another browser, on another computer, or after the data this site keeps in the browser has been cleared, choose again. It does not affect generated documents, exported Word files or exported pictures. Serif titles are drawn with Source Han Serif (Noto Serif CJK) or the system's Songti where one is installed; elsewhere the system picks a serif typeface for them.

## 12 The stages of work

In a task with an overall analysis (总体分析) - the requirements task is one - the assistant works in six stages. The stages are there so that the matter is thought through before use cases, requirements and constraints are written. To learn which stage the task is in, ask the assistant where things stand and what is still missing; it answers from the task's actual state.

| Stage | Whose pace | What the assistant does | What counts as enough |
|---|---|---|---|
| 核读材料 (reading the materials) | the assistant, in one go | reads all the materials and writes one topic page for each term, role, flow and goal the materials state, copying their words; records one problem for each place where the materials disagree; then says in a short paragraph what business the materials are about, what is to change and what the biggest uncertainty is | every material is cited by at least one topic page or problem |
| 澄清 (clarifying) | yours, one question at a time | asks only the one thing that affects most of the rest; offers a candidate before asking; records your answers on the topic pages and turns what you decide into a page labelled 决定 ("decision") | no labelled page has an open question waiting on it; every decision has its reason |
| 整理建模 (putting the topics in order) | the assistant, in one go | draws the topic pages as diagrams in a fixed order: the system boundary diagram, the use case diagram, the object relation diagram, a flowchart with branches for every flow page and a state diagram for every concept that has states; then reads through the 已经定下的 of all pages and records rules that contradict each other as problems for you to decide; finally reports what it drew and what is still lacking | every role is in the system boundary diagram and the use case diagram; every concept has a relation in the object relation diagram; every flow page has a flowchart with a decision; every concept that speaks of states has a state diagram; no two pages share a name; no page is without a label; no rule conflict is still open |
| 写条目 (writing items) | the assistant in one go, you item by item | writes use cases, non-functional requirements and constraints from the diagrams of the modeling stage and the topic pages you have looked at; every use case cites the use case diagram and its own flowchart | every flow and scene page has a use case based on it (directly, or through a diagram drawn from it); you have looked at every page an item is based on; you have looked at every diagram an item is based on; no item waits to be verified; no question that blocks the next stage is still open; no diagram, page or item still carries a 待定 ("undecided") mark |
| 评审确认 (review and confirmation) | yours, item by item | changes items as the review says; when you ask, or when the completion conditions are met, proposes entering the document stage | the review has no finding left open; all completion conditions are met |
| 编写文档 (writing the document) | the assistant in one go, you read it through | reads the business description and the confirmed items through, adds an introduction page for every chapter that has content, adds an opening sentence to a section that lacks one, and checks that terms and wording agree across the chapters; every addition states what it is based on and waits for you to read it | every chapter with content has an introduction; every concept has an explanation that you have verified; no question that blocks the next stage is still open |

**How the stage moves.** A new task is idle: no activity is in progress, and the assistant only writes topic pages and records questions, without proposing any stage. Click 启动首次分析 ("launch the first analysis") under 开展一项活动 ("start an activity") on the task status card and the task enters the flow of the first analysis (in the reading stage when it has materials, in the clarifying stage when it has none); while the business description is still empty, 通读材料起草 and 逐项澄清 launch it as well. Only you move the stage; the assistant cannot. Every step forward: when the assistant has finished a stage it sends a card that says how far the stage got and what the next stage will do, with two options, one that enters the next stage (进入澄清 "enter clarifying", 进入整理建模 "enter putting the topics in order", 开始写条目 "start writing items", 进入评审确认 "enter review and confirmation", 进入编写文档 "enter writing the document") and one that stays, which reads 继续本阶段 ("stay in this stage") on all five cards. When you choose the first, the assistant starts on the next stage at once; when you choose 继续本阶段, the card is only marked as answered and the assistant does not start working, so just go on and tell it what to add or change. In the reading, modeling and item-writing stages the assistant proposes as soon as it has finished; clarifying and review go at your pace, so there it does not push: while clarifying it does not propose as long as you are still talking or it still has something to ask, and proposes as usual once nothing is left to ask (what remains is what you could not answer, what you said to leave for now, or what does not block); in review it proposes when you ask or when the completion conditions are met. A card lists only the few pages that matter most for you to look at first and sums up the rest in a sentence. Every move is recorded.

**Going back to an earlier stage.** Going back is also your click. Only when most of the earlier results can no longer be used (for example, you added a new material, or several pages contradict each other) does the assistant send a card that proposes going back and says why, with two options: the one that goes back (one of 退回核读材料, 退回澄清, 退回整理建模, 退回写条目, 退回评审确认 - "back to" the stage named) and 留在本段 ("stay in this stage"). When you choose to go back, the task returns to that stage and the assistant continues from there; when you choose 留在本段, the card is only marked as answered and the proposal stays open.

**An unclear point does not send the task back.** When the assistant meets one unclear point in any stage (for example, a branch of a flow that has not been decided), it does not go back to clarifying for it: it records a question, writes 待定 ("undecided") on the page, diagram or item concerned, and carries on with the stage; when it reports at the end of the stage and when it sends the card for the next stage, it lists the questions still open for you to answer. Questions are of two kinds: one that **blocks the next stage** (阻断下游) is one without which the next stage cannot be done - these come first and you are asked to answer them first; one that **does not block** (不阻断) can wait, and says when to come back to it. After you answer, the assistant writes the answer into the page, diagram or item, removes 待定 and goes on to the next question; for the questions answered so far it asks once at the end, on one card, whether they are settled, and after your click records on each question where the answer went. When you say there is no answer yet, it keeps the question open and does not ask the same thing again in other words. In 待澄清事项 ("open questions") of each section of the business description, every question carries a 阻断下游 or 不阻断 label, and questions that have been settled are listed below with 落实到：… ("written into: …").

**The 待决定 ("to be decided") line.** Once the assistant has sent a proposal card, its proposal stays open and a line 待决定 appears above the input box, with a button that is the card's acting option. There are three kinds of proposal and the line words each differently: for entering the next stage it reads 助手已提议进入某阶段 ("the assistant has proposed entering a stage"); for going back, 助手已提议退回某阶段 ("the assistant has proposed going back to a stage"); in the document stage, when you are asked to read the additions, 补写的 N 处待过目 ("N additions wait to be read"), with the button 看过了，生成文档 ("read, generate the document"). After you chose 继续本阶段 or 留在本段 and discussed and revised for as many turns as you like, you can act on the proposal from this line at any time, without finding the card again or asking the assistant to resend it. The line is also there in another session. It disappears, or is replaced, when the stage really moves, when the assistant sends a new proposal card, or when you have looked at all the pages you were asked to read.

**Starting an activity.** The lower part of the task status card is 开展一项活动 ("start an activity"); the card opens every new session, the first session of a new task included. It has three groups:

- **正在进行** ("in progress"): one line when an activity is in progress, for example 继续首次分析：写条目. It only tells you where the task is; it is not a button.
- **流程** ("flow"): the first analysis. The button reads 启动首次分析 before it has been walked, and 继续首次分析（从某阶段接着） afterwards: it resumes at the stage where it stopped, and nothing is lost.
- **单独开展** ("on its own"): reading, clarifying, modeling, writing items, reviewing and writing the document can each be done on its own, without walking the whole flow. Each says whether it can be started now: reading needs a material (还没有材料，先上传), modeling and writing items need a page in the business description (业务说明还没有页), reviewing and the document need items (还没有需求条目); an entry that cannot be started is greyed. 发布 ("publish") is left to a later version.

You do not have to choose: you can simply type in the input box, and the task stays idle. A click adds a line to the conversation, such as 界面操作：用户启动首次分析，从核读材料开始。; the assistant does not start working because of it, so tell it what to do next. Choosing another entry while an activity is in progress ends that activity, and the line ends with what was in progress before (原来在做：…); 继续首次分析 takes you back into the flow at any time.

An activity started on its own differs from a stage of the flow in one way: when it is done, the assistant reports it in a reply, with the line 助手汇报这项活动结束：…。任务现在空闲。 under it, and proposes no other stage; cards that enter or go back a stage do not count meanwhile, and the card says so and points to the task status card. When you upload a material while the task is idle, the assistant does not start reading on its own: it sends a card with 开始核读材料 ("start reading") and 先不开始 ("not now"), and 开始核读材料 launches the first analysis.

**The task status.** To see where the task stands, click 任务状况 ("task status") beside the input box, or type `/状况` in the input box and send it: a 任务状况 card is inserted into the conversation with the current stage and who moved the task there and when, the number of sections in each chapter of the business description and the open questions, the diagrams by kind, the requirement items by collection and how many of them you have confirmed, what the stage still lacks, and whether a proposal is waiting for your decision. The card is computed by the program from the task records; it does not go through the assistant and is not sent to it, so you can call it up at any time. Only 请助手说明下一步 ("ask the assistant for the next step") on the card asks the assistant to say something. When you open a new session in a task that already has topic pages, this card is the first thing in the conversation, under a small line 新建会话 · 助手从干净的上下文开始，交付物还是这一份 ("new session · the assistant starts from a clean context, the deliverable is the same"). The card is put into the conversation by the page and is not written into the session, so the cards you called up are gone after a refresh.

**Look at the topic pages before items are written.** The card with 开始写条目 lists the topic pages the assistant asks you to look at first. Items can only be based on topic pages you have opened, so look at those pages before you click. If you type that it may start, the assistant still sends the card for you to click; when the proposal is already open, it asks you to click the button in the 待决定 line instead of sending the card again. To skip the stages in between, tell the assistant to write the items now; it then sends the card with 开始写条目 directly.

**Writing the document, and 看过了，生成文档.** After the items have been reviewed and confirmed, the assistant proposes 进入编写文档. When you click it, the assistant reads the business description and the items through, adds an introduction page for every chapter that has content, and sends a card asking you to read them; the card lists the added pages and has two options, 看过了，生成文档 ("read, generate the document") and 需要修改 ("needs changes"). An introduction is shown at the top of its chapter page, with 助手补写，待过目 ("added by the assistant, waiting to be read") while you have not confirmed it; the contents on the left have a line 导语 ("introduction") under each chapter, before its sections, and clicking it opens that page, where you can confirm or edit it. When you choose 看过了，生成文档, the pages on the card are recorded as viewed and the page opens the generated document; the assistant does not say anything more because of it. When you choose 需要修改, the card is marked as answered; say what to change, and the assistant changes it and asks you to read again. In the generated document the introduction of chapter 1, 概述与范围 (overview and scope), comes first, that of 业务对象 (business objects) opens 术语与定义 (terms and definitions), and those of the other chapters open 总体描述 (general description), each starting with the chapter name. The task can be completed in both the review stage and the document stage.

**When you ask for something that belongs to another stage.** You can say anything at any time. When it belongs to the current stage, the assistant does it. When it belongs to an earlier stage and changes a page of the business description (add a rule, reword a page), the assistant changes that page directly and records the source, without going back. When it can only be done in a later stage (for example, you say "just write the use cases" while the assistant is reading the materials), it does not do so, and it does not repeat your words back to ask whether you agree: it tells you which stage the task is in and in which stage that can be done, and sends the card for you to click. When it has nothing to do with these requirements, it answers briefly and returns to what it was doing.

**Seven things you can do at any time.** Whatever stage the task is in, these can be done, they do not change the stage, and afterwards the assistant returns to what it was doing: asking and answering questions; changing a topic page, an item or a diagram; confirming what the assistant added; recording something you decided as a 决定 page; asking the assistant to retell its understanding; starting a review; looking at the task status. Whatever the assistant adds is first marked as waiting to be verified and does not count as settled until you confirm it.

**What you see on the page.** The ordinary page does not show which stage the task is in or what is still missing: the assistant tells you in the conversation and sends a card when it is time to move on. When the service runs in debug mode, the top of the 调试 (debug) tab of the side panel has a stage bar: the names of the six stages, the current one marked and the earlier ones filled in, and under them what the current stage still lacks (这一段还差), one sentence each; click a sentence and the page opens the first topic page or item concerned, or the materials tab of the side panel when it is a material. What is already complete is summed up as 其余 N 项已齐 ("the other N are complete"). These are hints and block nothing, and the bar is only for looking: you cannot change the stage by clicking it.

**Where to start.** While the business description has no page yet, its tab shows two buttons: 通读材料起草 ("read the materials and draft") lets the assistant read all the materials first and write pages for what they state (it is off while the task has no materials); 逐项澄清 ("clarify item by item") lets the assistant ask you one thing at a time right away. You can also just talk to the assistant without using either button. Both buttons are off while the assistant is working.

**Lines in the conversation.** When you enter the next stage or go back to an earlier one on a card, a line appears under your sentence: 界面操作：用户把任务从…移到…。 ("interface action: the user moved the task from … to …"). When you choose the option that changes nothing on a card, or 看过了，生成文档, the conversation gets a line 界面操作：用户选择继续本阶段 ("interface action: the user chose to stay in this stage"; or 留在本段, 需要修改, 看过了，生成文档). When you click a card left from earlier and the stage does not change, the card says so under your choice: 这次点击没有改变阶段：任务当时在…。 ("this click did not change the stage: the task was in …"). Before this version the assistant could move a task back by itself; replies from that time keep the line above them, 助手把任务退回…：理由 ("the assistant moved the task back to …: the reason").

**Tasks created earlier.** A task created by 0.4 (which has 领域说明, "domain notes", in this place) is not divided into stages and works as before. A task with stages that was created before this version can enter the document stage as usual, but its task definition lacks the field 导语所属章 ("chapter introduced") and the question fields 是否阻断下游 ("blocks the next stage"), 何时回看 ("when to come back") and 落实到 ("written into"): in such a task the assistant writes no introduction pages, questions carry no 阻断下游 or 不阻断 label, and the corresponding checks show as not applicable.
